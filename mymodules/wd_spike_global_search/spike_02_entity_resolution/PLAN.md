## 2. 验证问题

验证多个实体命中时，评分规则能否稳定区分唯一命中与候选展示：

1. 精确、简称、别名和拼音近似匹配是否有稳定评分差异；
2. 多字段命中时评分如何合并；
3. 分差阈值 30 是否能区分唯一命中和候选展示；
4. 候选截断后是否能感知还有更多候选；
5. 同一输入是否得到完全一致的排序和决策。

## 4. 测试范围

- `res.partner` 中 1,000 条带 `GS02-` 标记的测试记录；
- 完全同名、简称、别名、拼音近似和大小写差异；
- 单字段和多字段评分；
- 唯一命中阈值 30；
- 候选最大数量 10；
- 稳定排序与候选截断提示。

## 5. 评分模型

本 Spike 使用可解释的技术验证模型，不冻结生产公式：

| 匹配类型 | 基础分 |
|---|---:|
| 名称精确匹配 | 100 |
| 名称大小写归一化匹配 | 95 |
| 简称匹配 | 80 |
| 别名匹配 | 70 |
| 拼音近似匹配 | 60 |
| 多字段额外命中 | +10，最多 +20 |

最终排序键为 `(score DESC, id ASC)`，以验证相同输入下结果稳定。

## 6. 成功标准

| 项目 | 成功标准 |
|---|---|
| 评分差异 | 精确 > 简称 > 别名 > 拼音近似 |
| 多字段合并 | 额外命中可解释地增加分数且不超过上限 |
| 阈值 | 分差 >= 30 进入唯一命中，分差 < 30 展示候选 |
| 截断 | 最多返回 10 个候选，并明确 `has_more=true` |
| 稳定性 | 同输入重复执行的决策、分数和 ID 顺序完全一致 |

## 7. 约束
