## 1 业务背景与目标

### 1.1 业务背景

用户需要在 Odoo 聊天界面以业务语言描述要查找的记录，并获得现有全局搜索能力实际找到的结果。用户不应为了搜索而先学习资源、字段或系统内部术语。

聊天助手承担自然语言交互和意图表达；既有全局搜索能力负责确定可搜索资源、条件校验、权限过滤和结果提供。此桥接不建立第二套搜索业务规则。

### 1.2 当前问题

- 用户需要在搜索界面中自行拆解业务表达，并理解现有条件的输入方式。
- 用户在对话中提出的资源、状态或日期条件可能不受当前搜索配置支持；若系统猜测，可能给出误导结果。
- 对话助手的结果必须与用户实际有权访问的全局搜索结果一致，不能凭模型生成的内容代替搜索事实。

### 1.3 业务目标

- 让具备全局搜索使用权限的用户能够通过聊天表达搜索意图，并收到真实全局搜索结果。
- 当表达无法映射到已支持的搜索范围或条件时，明确澄清或说明不支持，不静默猜测。
- 保持结果访问范围与用户在全局搜索中的既有权限一致，不扩大数据可见范围。

本文不设定未经测量的准确率、响应时限或效率提升百分比。

### 1.4 顶层产品约束

- **聊天是全局搜索的交互入口。** 聊天负责理解和呈现，不取代全局搜索的业务执行规则。
- **搜索助手只读。** 对话中不得创建、修改或删除业务记录。
- **权限不得扩大。** 聊天得到的记录范围不超过发起用户在全局搜索中可访问的范围。
- **不确定时不猜。** 未配置或有歧义的资源 / 条件必须进入澄清或安全拒绝路径。
- **结果必须可信。** 命中记录、数量、应用条件和可打开的记录入口必须对应实际搜索结果。

## 2 产品定位与上下文

### 2.1 能力类型

已有全局搜索能力的聊天交互适配能力。

### 2.2 使用主体

已登录且具备现有全局搜索使用权限的 Odoo 用户。是否还需限定为特定用户群或专用 Assistant 的可见范围，待业务负责人确认，见 `OPEN-LLM-01`。

### 2.3 服务范围

面向 Odoo 内已发布搜索配置所允许、且当前用户有权访问的业务资源。本文不扩大既有 Global Search 服务范围。

### 2.4 复用范围

- 供 Odoo 聊天用户发起全局搜索并查看结果。
- 本期不定义其他业务模块通过程序接口复用聊天助手的能力。
- 是否允许同一搜索助手面向全部授权用户，待确认。

### 2.5 上下游关系

| 方向 | 对象 | 关系说明 |
|---|---|---|
| 上游（使用者） | 已登录的 Odoo 全局搜索用户 | 用自然语言提交搜索意图并查看结果 |
| 下游（业务能力） | 现有全局搜索 | 按已发布搜索范围和发起用户权限执行搜索，并提供真实结果 |
| 下游（语言能力） | 语言模型服务 | 理解用户表达并组织对话；不能代替搜索结果事实 |

### 2.6 依赖方向

- 聊天助手依赖既有全局搜索能力获取记录，不自行定义搜索语义或扩展数据范围。
- 全局搜索能力不依赖聊天助手，继续独立工作。
- 聊天助手不得成为创建、修改、删除业务记录的入口。

## 3 范围

### 3.1 本期范围（In Scope）

- 用户在聊天框输入自然语言搜索请求。
- 将用户明确表达的资源、关键词及受支持条件用于现有全局搜索。
- 多个明确条件同时成立时，按“全部满足”执行搜索。
- 对不支持或有歧义的条件进行澄清或明确拒绝，不擅自替用户决定。
- 本期范围包含在聊天中展示搜索记录、命中数量、实际应用条件和可安全打开记录的入口；结果摘要、条目数量及分页交互的最低验收边界以 `FR-LLM-05`、`AC-05` 为准，界面细节可作为后续产品决策补充，但不得改变该业务边界。用户继续查看后续结果时，范围仍受当前用户权限约束。
- 在同一对话中对上一条成功搜索作明确追问时，按 `FR-LLM-08` 处理上下文。

### 3.2 明确排除（Out of Scope）

- 业务问答、财务 / 库存聚合、KPI、分析、推断或基于搜索结果进行未经定义的业务计算。原因：超出记录发现范围；归属待定的后续需求。
- 创建、修改、删除或审批业务记录。原因：本助手只提供只读搜索。
- 搜索未被既有全局搜索配置允许的字段 / 资源、聊天记录、附件正文或外部数据源。原因：不扩大既有搜索边界。
- 任意布尔表达式、排除词或由模型生成的底层查询语法。原因：本期仅处理既有搜索服务允许的表达。
- 对所有自然语言表达、所有语言、所有业务术语或未配置状态作出完整解析保证。原因：只能对已明确支持的资源和条件承诺。
- 新建保存 / 分享搜索、跨对话长期记忆或个性化推荐。原因：本期无相应业务需求；同一对话中的短期追问按 `FR-LLM-08` 单独处理。

## 5 功能需求

### 5.1 自然语言搜索与结果

#### `FR-LLM-01` 在聊天中发起全局搜索

**触发条件：** `ROLE-LLM-01` 在聊天助手中提交一条搜索请求。  
**业务行为：** 助手从用户表达中提取明确的搜索意图，并请求既有全局搜索能力查找记录。  
**业务结果：** 用户在当前对话中收到搜索结果或明确的无结果 / 需澄清 / 不支持反馈。  
**异常 / 边界：** 未提交可识别搜索意图时，助手应询问用户要查找什么，不得生成虚构命中记录。

#### `FR-LLM-02` 遵守当前用户搜索范围

**触发条件：** 搜索请求被接受执行。  
**业务行为：** 搜索只使用已发布配置允许的资源，并按发起用户的既有搜索权限筛选资源和记录。  
**业务结果：** 对话只返回用户有权访问的真实记录。  
**异常 / 边界：** 无可搜索资源或配置不可用时，助手明确告知无法搜索；不得扩大范围、切换其他用户权限或返回未校验数据。

#### `FR-LLM-03` 应用用户表达的多个条件

**触发条件：** 用户在一次搜索表达中明确给出多个受支持条件。  
**业务行为：** 助手将条件作为同一搜索意图提交；所有条件同时成立才视为命中。  
**业务结果：** 返回符合所有有效条件的记录，并说明实际应用的条件。  
**异常 / 边界：** 条件彼此冲突、无法映射或不适用于请求资源时，按 `FR-LLM-04` 澄清或拒绝。互斥日期范围、互斥状态等逻辑冲突必须请求用户澄清，不得静默选择其中一个条件或丢弃条件后执行。

#### `FR-LLM-04` 澄清不支持或有歧义的表达

**触发条件：** 用户使用的资源、字段、状态、日期或其他条件未被当前搜索配置支持，或表达有多种可能解释。  
**业务行为：** 助手说明无法确定的部分，并请求用户澄清；如只能应用部分条件，必须在执行前取得用户确认。  
**业务结果：** 用户可修正请求；系统只在条件清晰且获支持后执行相应搜索。  
**异常 / 边界：** 无法澄清或用户不确认时，不执行带猜测条件的搜索。

#### `FR-LLM-05` 返回真实结果及可用导航

**触发条件：** 既有全局搜索返回一页或多页结果。  
**业务行为：** 助手展示服务实际返回的记录摘要、命中数量及真实生效条件；对当前用户有权打开且具备有效导航入口的记录，提供打开入口。  
**业务结果：** 用户能够识别搜索结果并打开有权访问的记录；如有后续结果，助手告知是否还能继续查看。  
**异常 / 边界：** 无权、删除或无法安全导航的记录不提供打开入口；助手不得生成搜索结果中不存在的记录、数量、条件或链接。

#### `FR-LLM-06` 如实反馈无结果或搜索异常

**触发条件：** 搜索无命中、部分资源失败、服务不可用或输入无法满足搜索要求。  
**业务行为：** 助手按实际搜索结局说明无结果、部分结果或暂时无法完成，并在适用时保留真实成功结果。  
**业务结果：** 用户能够区分“确实没有命中”和“搜索未能完成”。  
**异常 / 边界：** 助手不得把错误伪装为零命中，也不得暴露其他用户可访问的资源、内部错误详情或敏感凭证。

#### `FR-LLM-07` 仅提供只读搜索能力

**触发条件：** 用户通过该聊天助手提出业务操作请求，或尝试调用搜索以外的能力。  
**业务行为：** 助手仅提供搜索相关只读能力；对创建、修改、删除、审批等请求明确说明当前助手不支持。  
**业务结果：** 业务记录保持不变，不产生搜索以外的业务副作用。  
**异常 / 边界：** 不得因用户要求、模型生成或界面配置变化而启用未批准的写操作。

#### `FR-LLM-08` 处理同一对话中的明确追问

**触发条件：** 用户在同一对话中，紧接上一条成功搜索后提交明确指向该搜索的追问，例如“那这个月呢？”。  
**业务行为：** 助手仅继承上一条成功搜索中已确认的资源范围、关键词和条件；将用户明确提出的新条件应用为新增或替换条件，并向用户说明本次实际条件。用户另起新主题、引用不明确或上一条搜索未成功时，不继承旧搜索条件。  
**业务结果：** 用户可以通过明确追问细化搜索，无需重复输入已确认条件；搜索结果仍按 `FR-LLM-02` 的权限范围生成。  
**异常 / 边界：** 追问与继承条件冲突、无法确定是新增还是替换，或所需条件不受支持时，按 `FR-LLM-04` 澄清；不得猜测继承内容。此规则只在同一对话中紧接上一条成功搜索的明确追问时适用，不形成跨对话记忆。

| `BR-LLM-07` | 模型生成的文本不得作为记录、数量、生效条件或链接的来源；这些事实只能来自实际搜索结果及其可用记录入口。 | 阻断 | `FR-LLM-05`、`FR-LLM-06` |

### 6.1 业务异常 vs 基础设施异常

| 类型 | 含义 | 业务处理 |
|---|---|---|
| 业务异常 | 请求有歧义、条件不支持、无可搜索资源或没有命中 | 请求澄清 / 说明不支持；真实无命中明确反馈 |
| 基础设施异常 | 搜索能力或语言模型服务暂时不可用、请求超时 | 告知用户搜索未完成；不得伪报无命中；保留用户重新发起请求的能力 |

| 已有全局搜索能力 | Odoo 内部业务能力 | 提供已发布资源范围、权限内记录和搜索结局 | 是 |
| 自然语言理解能力 | 外部 / 平台语言能力 | 理解用户表达并生成对话澄清或摘要 | 是 |
| Odoo 用户会话 | 平台能力 | 确认发起用户和其既有数据访问范围 | 是 |

### 9.2 外部系统 / 服务

语言模型服务用于理解用户输入及组织对话文本。若该能力不可用，系统不得伪造搜索结果；用户可在服务恢复后重新发起请求。其具体提供方、连接协议和运行参数属于 TDD / 部署决策。

### 9.3 上线前置条件

- 桥接 SRS、适用 DDD / TV 和 TDD 已按项目工作流批准并冻结。
- 全局搜索已存在有效发布配置，业务管理员已确认允许搜索的资源和字段。
- 已确认本期目标用户范围内至少一类用户可在已发布搜索范围中访问至少一个业务资源；该已发布范围须经过业务验证。
- 目标用户已有且验证过的全局搜索访问权限。
- 助手开放用户范围、澄清与结果展示要求已由需求负责人确认。
- 部署方已确认语言模型服务可用，并完成适用的数据处理与保密评估。

| `AC-10` | `FR-LLM-03`、`FR-LLM-04`、`BR-LLM-03` | 用户提出互斥日期范围或互斥状态 | 助手处理请求 | 助手请求澄清；未得到澄清前不任选一个条件执行搜索 |
