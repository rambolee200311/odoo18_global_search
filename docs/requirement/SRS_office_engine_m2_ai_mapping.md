## 0 文档说明

### 0.1 目的与权威范围

本文定义 Odoo 业务用户通过 Odoo-LLM 聊天，把自然语言需求、Office 模板结构和经 Odoo 授权的数据源字段映射为可由 M1 执行的 Mapping Plan，并在用户确认后生成文件的业务要求。本文也定义个人导出 Skill 的保存与复用要求。

本文定义业务行为，不定义接口实现、提示词文本、JSON Schema 的技术编码、模型字段、数据库表、队列或前端框架。

### 0.2 基线、已知事实与范围冲突

1. M1 最终交付报告总体判定为 **PARTIAL**，但对 M2 首期可用能力有明确样本证据：复杂 `.xlsx` 样本完成聊天上传、生成、独立回读和浏览器下载；基础 `.docx` 结构完成服务端读取、写入和独立回读，聊天输入/输出附件卡片可见，但浏览器文件选择器上传和下载仍为 `NOT VERIFIED`。`.xls` 与 `.doc` 当前关闭。详见 [M1 最终交付报告](../implementation/office-engine-m1/M1-FINAL-DELIVERY-REPORT.md)、[CC-006 ATR](../implementation/office-engine-m1/CC-OFFICE-M1-006/ATR-OFFICE-ENGINE-M1-CHAT-ADAPTER.md) 及 [复杂 Word 验证报告](../verification/Complex_Word_Chat_Render_E2E_20261022.md)。

## 1 引言

### 1.1 业务背景

M1 提供确定性的 Office 文件结构读取、受控写入、回读校验和 Odoo 附件交付底座。M1 不理解用户说的业务含义，也不负责推断模板中的自然语言填写说明应对应哪个 Odoo 字段。

M2 在聊天中承担“翻译官”职责：结合用户请求、模板中可识别的结构/文字和当前用户获准使用的 Odoo 字段字典，提出结构化映射；用户检查并纠正映射后，系统才可将确认的映射交给 M1 生成文件。映射成功后，用户可选择保存不含业务记录值的个人 Skill，以复用稳定的映射规则。

### 1.2 目标

- 让业务用户用自然语言指定模板用途和 Odoo 记录，减少手工逐格寻找字段的工作。
- 使 AI 的输出成为可检查、可修正、可拒绝的映射建议，不成为绕过 Odoo 权限或文件校验的执行主体。
- 让用户在成功生成后自愿沉淀个人私有导出 Skill；后续匹配时跳过映射推理，并实时读取目标记录的当前数据。
- 对无法识别、无权限、信息不足或服务失败的情况给出明确结果，不编造字段、数据或成功状态。

### 1.3 顶层产品约束

1. **AI 只建议映射**：AI 不直接访问业务数据源、不读写服务器文件、不执行代码；数据查询和文件渲染由受控 Odoo 能力完成。
2. **用户确认后才生成**：首次映射或映射发生变化时，未解决的阻断问题必须澄清；用户确认映射前不得生成最终文件。
3. **事实有权威来源**：字段、记录值、匹配数量、目标元素和文件生成状态必须来自 Odoo 或 M1；模型文本不能替代这些事实。
4. **Skill 只存规则**：Skill 不存储业务记录的实际值、模板文件内容或本次生成结果；每次执行均使用当前用户权限实时取数。
5. **不确定时停止**：未知字段、目标位置、冲突、权限不足或无法安全识别的结构必须澄清或拒绝，不能静默猜测。

### 1.4 术语

| 术语 | 定义 |
|---|---|
| 模板结构 | M1 能可靠识别并以受控形式提供的工作表、单元格、段落、表格、坐标及文本提示等结构信息 |
| Odoo 数据源字典 | 由受控 Odoo 查询能力针对当前用户、指定记录提供的可用模型/字段标识、类型和必要样例；不等同于任意模型元数据 |
| 映射建议 | AI 提出的目标元素到获准 Odoo 字段/允许值的结构化对应关系，供用户审阅和修正 |
| Mapping Plan | 经过服务端校验、包含明确目标、允许操作和值语义、可由 M1 接收的映射数据 |
| 预提取样例 | 供用户理解映射的最小必要字段值示例；不是最终文件的权威数据源 |
| 导出 Skill | 用户明确保存的、与模板结构和 Odoo 模型关联的可复用映射规则；不包含实际业务记录值 |
| 模板特征标识 | 系统为可匹配模板结构生成的标识；其计算方法和归一化规则不在本 SRS 定义 |

## 2 总体描述

### 2.1 产品定位

M2 是 M1 Office 引擎之上的聊天映射与导出编排能力。它理解用户意图并提出映射，呈现确认/纠错交互，之后调用 Odoo 授权查询和 M1 渲染能力。M2 不替代 Odoo 业务流程，不执行审批、记账或其他业务写入。

### 2.2 使用主体

业务用户是主要操作者。系统管理员或部署负责人负责提供经批准的安全字段基线和外部 AI 数据使用策略；这不自动授予其读取业务记录的权限。

### 2.3 使用场景

用户在聊天中上传一个受支持模板并表达需求，例如：“用销售订单 S00001 填这个表”。系统识别目标记录、读取模板结构和允许的数据字典，提出映射卡片。用户可以修改、删除或确认映射。确认后，系统再次按当前权限读取最新记录值，调用 M1 生成并验证文件，再把结果作为受控聊天附件交付。若用户选择保存 Skill，后续在同结构模板和兼容模型场景中可复用映射规则。

### 2.4 假设、依赖和约束

- 用户有权访问聊天线程、上传模板和指定的 Odoo 记录。
- 部署已批准允许发送给 AI Provider 的模板内容、业务字段类别和数据处理政策；未批准时不得发送。
- M2 只能使用当前用户有权访问且经部署安全字段基线允许的字段；若可用字段集合为空，系统不得把业务字段发送给 AI。
- M1 必须已对当前文件格式/结构开放对应读取、渲染和回读能力。M1 失败时，M2 不得显示成功文件。
- 现有 `odoo_record_retriever` 是本轮明确要求使用的授权数据查询能力；它的精确输入输出和权限行为需在下游 TDD 中核验，SRS 不预设其实现契约。

## 3 范围

### 3.1 本期范围（In Scope）

- 聊天中的自然语言意图识别、模板结构理解及目标记录/模型确认。
- 通过授权查询能力取得当前用户可使用的数据源字典和必要样例。
- AI 生成结构化映射建议，识别歧义并发起澄清。
- 映射确认卡片展示、人工修正、确认和拒绝。
- 确认后实时取数并将经验证的 Mapping Plan 交给 M1，展示生成结果。
- 个人私有导出 Skill 的保存、精确匹配和复用（范围依据总 SRS V1.1.0）。

### 3.2 明确排除（Out of Scope）

| 排除项 | 原因与归属 |
|---|---|
| Office 底层解析、写入、格式转换、公式/版式校验 | 属 M1；M2 调用其已开放能力，不复制实现 |
| 文件导入、从 Office 创建/更新 Odoo 业务记录 | 属后续独立需求；本 SRS 只覆盖 Odoo 到文件的导出 |
| 任意业务问答、利润计算、预测、经营分析或替代报表 | 不属于模板映射；应引导用户使用相应 Odoo 报表或业务流程 |
| AI 直接执行 Python、任意文件/网络访问或任意 ORM 查询 | 违反顶层产品约束 |
| 公共 Skill 发布申请、审核、跨用户/跨公司共享、企业版本治理 | 冻结总 SRS 将完整 Skill 生命周期列为 M3；需另行决策是否提前调整 |
| 任意未验证 Office 格式/结构的兼容承诺 | 受 M1 格式准入和能力证据约束 |
| 批量多模板或多根记录生成 | 不在本期单次请求范围；按总 SRS 的批量排除项处理 |

### 3.3 后续候选

| 阶段 | 候选能力 |
|---|---|
| M3 或另行批准 | 公共 Skill 发布/审核、团队共享、版本治理、停用/撤销与测试文件隔离 |
| 待定 | 映射运行指标、模型辅助解释、多模板批量处理及更广泛的 Office 结构支持 |

## 5 功能需求

### 5.1 意图识别、上下文收集与授权取数

#### FR-M2-001 自然语言导出请求识别

**触发条件：** 业务用户在聊天中提交模板并说明希望使用的 Odoo 模型/记录或其业务标识。
**业务行为：** 系统识别这是文件导出请求，收集模板、目标记录、目标模型及用户明确提出的填充要求。若模型/记录不能唯一确定，系统必须询问用户。
**业务结果：** 建立一项只关联当前线程、当前用户和单一模板/单一根记录的映射请求。
**异常 / 边界：** 用户提出导入、业务分析或写入 Odoo 的要求时，按 §3.2 引导或拒绝；不得擅自选择记录。

#### FR-M2-002 模板结构与文字提示收集

**触发条件：** 请求包含用户有权访问且 M1 已开放的 Office 模板。
**业务行为：** 系统取得 M1 能可靠提供的结构元素和模板可见文字，供映射分析使用；对无法识别的结构应标明未识别。
**业务结果：** 映射分析仅针对已识别并可由 M1 接收的目标元素进行。
**异常 / 边界：** 模板格式、结构或附件访问不满足 M1 当前开放能力时，明确说明原因并停止；不得声称已经完整读取。

#### FR-M2-003 通过授权查询能力取得数据字典

**触发条件：** 用户指定的模型和记录已明确，且请求通过业务权限检查。
**业务行为：** 系统调用 `odoo_record_retriever` 所代表的现有授权查询能力，取得当前用户可访问的该记录字段标识、字段类型及映射所需的最小样例；字段必须同时满足 Odoo 当前权限和已批准字段基线。
**业务结果：** AI 只能依据返回的数据字典提出字段映射；不符合交集的字段和值不得提供给 AI。
**异常 / 边界：** 记录不存在、用户无权、字段不在允许基线、查询超时或失败时，给出对应的受控错误/澄清提示，不得伪造数据或继续生成。

### 5.2 AI 映射建议与澄清

#### FR-M2-004 生成受约束的结构化映射建议

**触发条件：** 模板结构、用户意图和数据字典已可用。
**业务行为：** AI 将目标元素映射至数据字典中的真实字段标识，并形成符合 M1 Mapping Plan 业务契约的结构化 JSON 建议；机器可读的映射输出必须是合法 JSON，不得夹带 Markdown、代码或自然语言前后缀；可表达无法映射、需要澄清和不应用的目标。目标元素、字段、操作和值类型必须来自已提供的上下文和已允许集合。
**业务结果：** 系统得到可被服务端校验并展示给用户的映射建议，不产生文件。
**异常 / 边界：** 非法 JSON、未知字段、未知目标、未支持操作/类型或不完整映射不得进入确认或渲染；不得把自然语言说明当作可执行内容。

#### FR-M2-005 歧义、缺失与冲突澄清

**触发条件：** 模板指令不清、字段候选不唯一、必填目标无来源、用户条件冲突或 AI 无法基于授权信息建立映射。
**业务行为：** 系统指出具体目标位置和待澄清原因，询问用户补充信息或从合法候选中选择。对可明确跳过的非必填目标，系统须向用户展示跳过影响并取得确认。
**业务结果：** 只有阻断问题解决后，请求才可进入映射确认；系统保留未解决问题状态。
**异常 / 边界：** 用户未回答、回答仍不明确或字段无权使用时，不得猜测、静默删掉条件或生成文件。

### 5.3 映射确认与纠错

#### FR-M2-006 映射确认卡片

**触发条件：** 服务端已验证映射建议的结构及允许集合，且没有未解决的阻断问题。
**业务行为：** 聊天界面展示映射确认卡片。每条映射至少显示模板目标位置/元素、Odoo 模型与字段名称、数据类型、预提取样例及需要用户注意的说明；未映射和待澄清项须可辨认。
**业务结果：** 用户可以查看完整待确认映射，并选择修改、确认或取消。
**异常 / 边界：** 任何字段样例不属于当前用户可见范围时不得显示；卡片无法完整呈现映射时不得将其视为已确认。

#### FR-M2-007 用户修改映射

**触发条件：** 用户在确认卡片中选择修改映射。
**业务行为：** 用户可将目标元素改为另一个已授权且在数据字典中的字段、调整允许的映射关系、明确跳过非必填项，或按产品允许的规则提供固定文本。系统对每次变更重新校验。
**业务结果：** 修改后的映射以待确认状态展示，只有用户再次明确确认后方可执行。
**异常 / 边界：** 用户输入未知字段、越权字段、非法目标/类型或不支持操作时，拒绝该修改并说明原因；不得因用户编辑绕过服务端校验。

#### FR-M2-008 映射确认与生成授权

**触发条件：** 用户对当前完整映射卡片执行明确确认。
**业务行为：** 系统记录确认对应的模板、目标记录、映射版本和当前会话；确认后重新检查用户权限并实时读取最新记录数据，再将服务端校验后的 Mapping Plan 交给 M1。
**业务结果：** 仅确认版本可用于本次渲染；M1 的回读/安全校验通过后，输出文件作为当前线程受控附件返回。
**异常 / 边界：** 确认后映射、记录、权限或模板发生变化时，系统必须要求重新确认或停止；M1 失败、回读不通过或附件交付失败时不得报告成功或提供失败候选文件。

### 5.4 私有导出 Skill 保存与复用

#### FR-M2-009 成功后保存为私有 Skill

**触发条件：** 本次文件已成功生成并通过 M1 校验，且用户选择“保存为 Skill”。
**业务行为：** 系统保存用户确认的映射规则、模板特征标识及绑定的 Odoo 模型，创建仅该用户可见的私有 Skill。映射规则记录字段引用和允许操作，不保存本次记录值、样例明文、模板原文件或输出文件。
**业务结果：** 用户可为 Skill 命名并在本人后续请求中查看、修改或停用；保存成功状态明确显示。
**异常 / 边界：** 文件生成未成功、用户未明确选择保存、模板/模型不兼容或保存违反隔离规则时，不得创建可用 Skill。

#### FR-M2-010 精确匹配并应用私有 Skill

**触发条件：** 用户提交新的导出请求，且上传模板的结构特征标识、目标模型与本人有效 Skill 唯一匹配。
**业务行为：** 系统可跳过 AI 映射推理，复用 Skill 中的映射规则；仍须检查当前用户/公司/记录权限，实时取得当前记录值，并按当前 M1 能力重新验证映射和输出。按冻结总 SRS 的默认规则，系统须向用户展示命中的 Skill、目标模型和本次目标记录摘要，并取得本次明确确认后才可生成；已验证 Skill 是否可免除逐项映射确认仍受总 SRS `OPEN-OFFICE-08` 约束。
**业务结果：** 在不调用 AI 重新推理映射的前提下，经用户确认后生成基于最新授权数据的文件；系统可展示命中的 Skill 名称和目标模型。
**异常 / 边界：** 无精确匹配、多个 Skill 同时匹配、模型不符、规则失效、权限变化或 M1 不支持当前结构时，不得任意选取或强行执行；应请求用户选择、重新映射或拒绝。

#### FR-M2-011 私有 Skill 修改、停用与隔离

**触发条件：** Skill 所有者查看本人 Skill 并执行修改或停用操作。
**业务行为：** 系统允许所有者修改映射规则；修改后该 Skill 在再次使用前必须经用户确认的成功导出验证。停用后不得自动匹配。
**业务结果：** Skill 变更与停用状态对所有者可见，并仅影响所有者后续请求。修改后的规则进入待验证状态；只有再次完成一次成功导出后，才可参与自动匹配。
**异常 / 边界：** 非所有者不得读取、修改或使用该 Skill；停用或待验证 Skill 不得因历史会话或模型输出重新启用或自动执行。

### 5.5 非导出请求与用户可见错误

#### FR-M2-012 限定业务问题范围

**触发条件：** 用户在聊天中提出独立于模板填写的业务分析或计算问题。
**业务行为：** 系统说明 M2 仅支持按已授权记录和明确映射填充 Office 模板，并引导用户使用相应 Odoo 报表或业务功能。
**业务结果：** 不把 AI 推测的计算或业务结论作为答案，不调用文件生成流程。
**异常 / 边界：** 用户请求同时包含导出与分析时，只继续已明确且可安全完成的导出请求；分析部分单独拒绝或引导。

#### FR-M2-013 查询与 Provider 失败处理

**触发条件：** AI Provider、授权记录查询或 M1 能力超时、失败或返回不可用结果。
**业务行为：** 系统向用户说明失败发生在哪一业务阶段，并保留可安全重试或重新提交的入口。
**业务结果：** 失败状态与“无匹配数据”明确区分；不存在伪造字段值、成功映射或下载文件。
**异常 / 边界：** 错误消息不得泄露密钥、内部提示词、其他用户数据或无权资源是否存在。

## 7 状态与生命周期

### 7.1 导出请求的业务状态

| 状态 | 业务含义 | 可进入条件 | 可执行动作 |
|---|---|---|---|
| 信息收集中 | 模板、模型、记录或用户要求尚未齐备 | 用户发起请求 | 补充信息或取消 |
| 待澄清 | 存在歧义、缺失或冲突 | 映射前/映射后发现阻断问题 | 回答问题或取消 |
| 待确认 | 映射建议通过结构与权限校验，等待用户确认 | 阻断问题已解决 | 修改、确认或取消 |
| 处理中 | 用户已确认，系统正在重新取数并请求 M1 生成 | 当前确认有效且权限仍通过 | 等待完成 |
| 已完成 | 文件生成及必要回读验证成功并已交付 | M1 和附件交付成功 | 查看/下载；可选择保存 Skill |
| 失败 | 查询、映射校验、生成或交付失败 | 任一必要步骤失败 | 查看受控原因并重新发起 |
| 已取消 | 用户取消本次请求 | 用户主动取消 | 不得继续生成 |

### 7.2 Skill 状态

| 状态 | 业务含义 | 可使用条件 |
|---|---|---|
| 有效 | 所有者保存且可参与匹配的私有 Skill | 所有者、公司、模板结构及模型匹配，且规则仍通过校验 |
| 待验证 | 所有者修改了映射规则，新的规则版本尚未通过成功导出验证 | 不参与自动匹配；所有者须完成一次成功导出后方可恢复有效 |
| 停用 | 所有者暂时关闭的 Skill | 不参与自动匹配；所有者可重新启用前须重新验证 |

### 7.3 禁止流转

- BR-M2-004：待确认或待澄清请求不得进入处理中。
- BR-M2-005：预提取样例或 Skill 旧值不得替代本次实时取数。
- BR-M2-008：Skill 匹配不得跳过权限或 M1 强制校验。
- 已取消、失败或停用的请求/Skill 不得因模型回复或客户端重试自动变为已完成/有效。

| AC-13 | FR-M2-009 | 文件生成失败或用户未选择保存 | 系统处理保存动作 | 不创建有效 Skill；失败文件的映射不能被静默沉淀 |
