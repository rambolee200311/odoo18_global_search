## 1. 变更控制

本文件是 V1.0.0 的受控变更，不覆盖历史文件。凡与本文件冲突的 V1.0.0 条款，以本文件为准。AI Provider、字段授权、Odoo 权限网关、M1 文件能力、私有 Skill 隔离、数据最小化及实时取数约束保持不变。

## 2. 被替换条款

### 2.1 FR-M2-006：自然语言提案与真实预览

Proposal 通过确定性校验后，系统使用 M1 生成真实、私有、与当前 Proposal 版本绑定的预览附件，并在聊天中以自然语言说明自动映射摘要、缺失项和下一步。M2 不再展示逐目标下拉映射卡片。存在阻断性必填缺失时不得生成可确认预览；系统必须说明缺失位置和原因，并允许用户在聊天输入框继续澄清。

### 2.2 FR-M2-007：多轮自然语言修改

用户可在聊天输入框用自然语言修改当前 Proposal。普通修改应基于已持久化 Proposal 做受控增量更新，未被指明的合法映射保持不变。每次修改都须经 Mapping Proposal 校验，形成新 Proposal 版本，并生成绑定新版本的预览。模板指纹或源业务记录数据指纹发生变化时，系统必须放弃增量修改并重新生成完整 Proposal；不能继续复用旧预览或旧确认。

无效或歧义修改不得改变当前有效 Proposal。预览失败时保留最新已校验 Proposal，明确告知用户预览未生成；不得丢失映射或提供未验证候选文件。

### 2.3 FR-M2-008：版本绑定确认与正式生成

用户通过聊天明确回复“确认/生成”授权当前 Proposal 版本。确认请求必须匹配当前 Session revision、Proposal revision 和该 Proposal 的已验证预览。生成正式文件前，系统须重新验证用户、公司、源附件、目标记录和字段权限，并通过授权 Retriever 重新读取数据。

若本次读取的数据指纹与预览指纹不同，系统不得静默生成。系统应以最新数据重新生成预览，说明数据已变化，并要求用户再次明确确认。只有确认仍绑定的最新预览版本且 M1 回读验证及附件交付均成功，才能返回正式附件。

## 3. 交互状态

Session 交互状态固定为：

`analyzing`、`preview_ready`、`revision_pending`、`confirmation_required`、`confirmed`、`generating`、`completed`、`failed`。

状态变化及并发保护由服务端执行。Proposal revision 标识映射规则版本；Session revision 用于乐观并发控制。客户端不得直接写入状态或 revision。

## 4. 预览与资源约束

预览必须调用 M1 的受控读写及独立回读校验能力。处理受 Odoo 配置的文件大小、扩展大小、内存和墙钟超时预算约束。候选预览只有在 M1 回读通过后才能作为私有 Odoo 附件展示。预览附件绑定当前 Session 和公司，不公开访问；新版本预览成功后可替换或清理旧预览，失败时保留已保存 Proposal。

并发预览通过 Session revision 乐观锁提交结果。耗时渲染期间不持有数据库行锁；候选完成后用短事务再次检查 revision，旧版本候选不得覆盖新版本预览。

## 5. 验收标准增补

| ID | Given | When | Then |
|---|---|---|---|
| AC-M2-025 | 首次请求的 Proposal 通过校验 | 系统创建预览 | 预览经 M1 回读后作为 Session 私有附件返回，且记录绑定当前 Proposal revision |
| AC-M2-026 | 当前预览有效 | 用户自然语言修改 B12 等一个或多个映射 | 系统仅更新受影响映射，重新校验并提供绑定新 Proposal revision 的预览 |
| AC-M2-027 | 预览仍对应当前 Proposal 和源数据 | 用户明确确认 | 系统重验授权及数据，调用 M1，成功后交付正式附件 |
| AC-M2-028 | 必填来源字段不存在或无权访问 | 系统分析/修改 Proposal | 系统说明具体缺失/权限原因，不编造数据且不允许确认生成 |
| AC-M2-029 | M1 预览生成失败 | Proposal 已校验并持久化 | Proposal 保留，状态/聊天明确说明失败，失败候选不可下载 |
| AC-M2-030 | 请求带有旧 Session revision，或并发修改已先提交 | 系统提交 Proposal/预览 | 系统拒绝旧写入，不覆盖较新 Proposal 或预览 |
| AC-M2-031 | 用户权限被撤销，或预览后源数据变化 | 用户确认生成 | 权限变化时拒绝；数据变化时刷新预览并要求再次确认，不静默生成 |
