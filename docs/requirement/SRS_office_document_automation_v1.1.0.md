## 1 引言

### 1.1 业务背景

3PL 企业及其业务伙伴使用的 CMR、装箱单、合同、对账单和自定义 Excel/Word 表格经常具有不同的版式、字段位置、公式和填写说明。模板可能没有机器占位符，填写规则可能只写在单元格、表格、段落或相邻标签中。

业务人员需要在 Odoo 记录与这些文档之间反复查找、复制和整理数据。现有 Odoo-LLM 可查询业务数据并处理部分附件，但当前源码没有确认 Office 结构化读取与模板写入能力，也明确将 Office 聊天附件标记为不支持。

### 1.2 目标

- 提供与具体业务模型解耦的 Office 文件读取、受控写入、格式校验和聊天交付底座。
- 允许用户指定符合系统准入规则的 Odoo 模型和记录，使用当前用户可读取的必要数据填充文档。
- 由 AI 解释模板与字段语义并提出结构化映射；由受控后端验证并应用映射。
- 在 M2 允许用户保存和复用本人私有导出 Skill；M3 完成公共 Skill 发布审核和完整生命周期治理。Skill 只保存执行规则，不存储业务数据。
- 让用户能够识别成功、待确认和失败状态，并检查最终文件。

本文不承诺任意模板均可一次自动正确完成，也不设未经验证的准确率、文件大小或处理时限指标。

### 1.3 顶层产品约束

1. **通用性：** 不将 CMR、采购订单、发票或某个客户模板写成核心业务特例。
2. **能力解耦：** AI 只提出结构化映射建议；受控后端读取数据、解析文件、校验映射、渲染文件和管理附件。
3. **数据权威：** Odoo 是业务记录事实来源；模型不得虚构或改写业务值。
4. **权限继承：** 所有记录、字段、附件和生成结果遵守当前用户的授权边界。
5. **只读业务数据：** 文档生成不能创建、修改、审批、签署或发送 Odoo 业务记录。
6. **Odoo 控权：** AI 不得直接访问业务数据源；所有业务数据必须由 Odoo 权限网关按当前用户权限提供。
7. **安全字段白名单：** AI 只能获得白名单与当前用户可读权限的交集字段。
8. **强制校验：** 结构、公式保留和生成文件回读校验均由后端强制执行，用户预览不得绕过。
9. **Skill 无数据与实时取数：** Skill 只保存执行规则和映射配置；每次执行必须通过 Odoo 权限网关实时读取最新业务数据。
10. **分阶段交付：** 严格按 M1 → M2 → M3 → M4 顺序实施；每阶段独立交付、独立验证并通过阶段门禁后，方可进入下一阶段。

### 1.4 术语

| 术语 | 定义 |
|---|---|
| Office 文件 | 本期指 Microsoft Office 工作簿和文档，包括现代格式 .xlsx、.docx 及旧版格式 .xls、.doc |
| 模板 | 用户提供、包含版式、内容、公式或填写说明的 Office 文件 |
| 映射计划 | 目标位置、业务数据来源及允许转换方式的结构化建议 |
| 根记录 | 用户指定的本次生成起点记录 |
| Skill | 经授权用户验证、可复用的执行规则库，包含模板特征和映射配置；不包含某次请求的业务数据 |
| Odoo 权限网关 | 按当前用户的模型/记录/字段访问权限、公司范围和安全字段策略读取业务数据的受控系统边界；AI 不直接访问其后面的业务数据源 |
| 通用文件操作底座 | 与具体业务模型无关的 Office 接收、读取、校验、渲染和附件交付能力 |

## 2 总体描述

### 2.1 产品定位

本能力定位为**由 AI 驱动、由 Odoo 控权、由用户参与学习的企业级文档自动化系统**。系统不追求全自主黑盒 Agent，而追求高度可控的确定性产出，并严格按四个独立里程碑演进：M1 Office 引擎底座、M2 AI 映射与个人私有导出 Skill 保存/复用、M3 公共 Skill 生命周期、M4 企业级治理与审计。

### 2.2 用户角色与使用场景

业务用户在聊天中附上模板并指定模型与记录，例如：“用销售订单 S00001 填这个 CMR”。系统确认记录身份和读取范围，读取模板结构及授权数据，生成待审阅映射计划；有歧义时请求澄清。用户确认后，系统生成新文件并在聊天中返回。M2 允许普通业务用户保存、修改和复用本人私有 Skill；公共发布申请、审核和公司范围使用在 M3 处理。系统管理员管理格式、模型策略和安全字段白名单。

### 2.3 业务流程概述

1. 用户提交文件及自然语言请求。
2. M1 检查文件并提取结构；任何预览或渲染均经过后端结构、公式保护和回读校验。
3. M2 由 Odoo 权限网关按当前用户实时读取允许的数据，再交给 AI 生成 Mapping Plan；AI 不直连业务数据源。
4. 用户处理澄清并确认映射，后端生成并回读验证文件。
5. M2 在成功生成后允许用户保存私有 Skill；后续匹配只复用规则，仍实时读取当前授权数据。
6. M3 提供公共 Skill 发布审核、公司范围管理和完整生命周期；M4 管理企业字段白名单、发布授权和审计追溯。
7. 聊天仅返回通过后端强制校验的文件、处理结论和需人工检查事项。

### 2.4 产品边界

本能力不替代 Odoo 业务流程，也不自动审批或提交生成的文件。业务记录、附件及用户确认是不同事实来源；Skill 只复用映射配置，不能作为权限凭证。当前源码能力与目标需求的差异见源码调查记录。

### 2.5 假设、依赖和约束

- Odoo-LLM 聊天和工具框架可由独立 Addon 扩展；真实兼容范围须在后续设计中验证。
- M1 文件接收受现有聊天用户、附件及线程访问规则约束。
- M2 依赖 Odoo 权限网关和可用的 LLM Provider；M2 起字段访问须同时符合用户权限和运行时安全白名单。
- M3 依赖 M1/M2 的独立验收结果；M4 依赖 M1/M2/M3 的独立验收结果。
- 当前源码调查未发现 Office 结构化读写库；本 SRS 不将特定库写成既有依赖或既定选择。
- 业务数据不得通过提升权限或其他方式绕过 Odoo 权限网关及当前用户授权提供给 AI。

## 3 范围与里程碑

### 3.1 Milestone 1：Office 引擎底座

独立提供 .xlsx/.docx/.xls/.doc 接收、格式和结构识别、结构化读取、受控渲染、公式/格式保护、输出回读验证、错误处理和附件交付。不依赖 AI 映射、业务模型或 Skill。旧版格式的具体可处理对象和保留边界须经代表性样本验证。预览和最终输出均必须通过同一组后端强制校验。

### 3.2 Milestone 2：AI 映射

基于 M1 已开放的文件能力，通过 Odoo 权限网关读取当前用户可访问且策略允许的实时业务数据；AI 仅接收网关提供的必要数据和模板结构，并生成结构化 Mapping Plan。包含确认、澄清、文档生成以及成功生成后的个人私有导出 Skill 保存、修改和复用。M2 首期只开放 `.xlsx` 和基础 `.docx`：复杂 XLSX 样本已有聊天上传、生成、回读和浏览器下载通过证据；基础 DOCX 的服务端读取/写入/回读和聊天附件卡片有通过证据，但浏览器文件选择器上传及下载尚未验证，必须在 DOCX 面向用户启用前完成对应 HVR。`.xls`、`.doc` 在 M2 首期继续拒绝；未验证的高级 Word 对象（包括宏/VBA、复杂 VML、文本框和未知对象）继续拒绝。此范围不声称 M1 全范围已验收。M2 起必须执行服务端默认拒绝的基线白名单与 Odoo 权限交集约束。M2 部署须通过安装初始化数据或部署配置提供最小、经批准且非敏感的基线字段集合，覆盖该部署代表性验收场景；M2 不提供白名单管理界面、任意增删改或企业级版本治理。M4 再交付白名单的企业级可配置治理能力。基线白名单未配置时，拒绝向 AI 提供业务字段。

### 3.3 Milestone 3：Skill 生命周期

在 M1/M2 已独立交付的能力上提供公共 Skill 发布申请、指定审核员查看原模板和 Mapping Plan、生成测试文件、批准/驳回、公司范围控制、公共版本管理、停用/撤销及审核附件隔离。个人私有 Skill 的基础保存、修改和复用由 M2 提供；M3 负责公共发布治理及更完整的生命周期。Skill 仅保存规则；每次应用都实时经 Odoo 权限网关取数。

### 3.4 Milestone 4：企业级治理与审计

提供安全字段白名单及模型准入策略的管理、版本与变更追溯；管理审核/发布授权和公司范围；对数据策略、Skill 生命周期、映射执行、强制校验、附件访问和处理结论形成可查询审计记录。

### 3.5 顺序实施与阶段验收门禁

阶段按 M1 → M2 → M3 → M4 顺序推进。下游工作可基于上游已通过且明确开放的能力开展；未验证能力必须保持关闭。M1 全范围未结项不自动否定已通过的 `.xlsx` 及基础 `.docx` 子范围，但 M2 面向用户的发布仍须通过本阶段对相关聊天路由、附件交付、权限和格式的验收门禁。该分范围推进不改变 M1 整体 `PARTIAL` 结论，也不把 CC-004/CC-005 历史状态改写为通过。

| 阶段 | 独立交付边界 | 阶段退出门禁 |
|---|---|---|
| M1 | 无 AI/业务数据依赖的 Office 文件引擎 | 每种格式仅在其能力 Gate 通过后开放；M1 总体验收仍按 M1 基线处理。未通过格式/结构明确拒绝（AC-01 至 AC-10、AC-23、AC-29 至 AC-31） |
| M2 | 通过 Odoo 权限网关的实时取数、AI Mapping Plan 与个人私有导出 Skill | 部署基线白名单已提供并默认拒绝；映射、确认、私有 Skill 隔离/复用验收通过。用户发布仅限 `.xlsx` 及基础 `.docx`；基础 DOCX UI HVR 通过前不开放该 UI 路径。依赖的聊天路由/附件交付与权限门禁须另有通过证据（AC-11 至 AC-14、AC-17、AC-19、AC-24、AC-27、AC-28、AC-32 至 AC-35） |
| M3 | 公共 Skill 发布、审核、安全复用和生命周期治理 | 公共发布审核、停用/撤销控制、测试文件隔离、审核附件权限和每次实时取数验收通过（AC-15、AC-16、AC-19、AC-21、AC-22、AC-25） |
| M4 | 企业白名单治理、授权和审计 | 管理策略变更/版本、字段默认拒绝、审计完整性和访问范围验收通过（AC-16、AC-20、AC-26） |

### 3.6 明确排除

| 排除项 | 原因与后续归属 |
|---|---|
| PDF、图片作为可填写模板 | 属于不同的解析技术栈（OCR、视觉理解或 PDF 结构处理），需独立需求与技术验证，另起平行 SRS；未来可在适用性评估后复用本文 M2/M3/M4 的 AI 映射、Skill 生命周期、权限和审计架构 |
| 演示文稿（.ppt/.pptx）作为可填写模板 | 非本期单据流转的高频核心格式，暂不纳入 |
| 旧版 .xls/.doc | M1 的长期格式目标不等于当前可用能力；M2 首期明确拒绝。只有代表性样本、格式保真和回读能力通过独立 Gate 并经范围变更后才可开放 |
| 任意 Python、宏、脚本执行或任意服务器路径访问 | 安全边界禁止，不属于后续授权能力 |
| 创建、修改、删除、审批、签署、发送 Odoo 业务记录 | 文档生成与业务交易处理职责不同，须独立需求评审 |
| 保证所有复杂 Office 对象无损保留 | 依赖实际格式能力；无法安全处理的文件应失败 |
| 多模板/多根记录批量生成、模板市场、跨公司共享 Skill | V1.0.0 每次生成限定一个模板和一个根记录；批量能力及跨公司共享另行评审 |
| 无人复核的法律、运输、财务或监管用途保证 | 输出是待人工检查的文件 |

## 4 角色与业务权限

## 5 功能需求

功能需求按 M1 至 M4 阶段组织；FR-PERM 为横切权限控制，分别在 M2/M3/M4 落地。P0/P1 优先级属于 V1.0.0 冻结基线，后续调整按 SRS 变更处理。

### 5.1 Milestone 1：通用 Office 文件操作底座

#### FR-M1-001 聊天附件接收（P0）

**触发/前置：** 已登录用户在 Odoo-LLM 聊天中附加 .xlsx、.docx、.xls 或 .doc 并提交消息。<br>
**行为：** 接收文件并与上传用户、所属聊天线程和用户消息关联；显示文件名及处理状态。附件访问和下载遵从聊天及附件授权。<br>
**异常：** 空文件、超出确认容量、无权使用的附件、文件内容与允许类型不符时拒绝处理并说明原因。聊天 UI 接受上传不代表文件可供 AI 使用。

#### FR-M1-002 文件类型与安全结构识别（P0）

**触发/前置：** M1 收到待解析附件。<br>
**行为：** 对 .xlsx、.docx、.xls 和 .doc 核对扩展名、实际内容特征和媒体类型的一致性；识别损坏、加密、格式不匹配或异常压缩/复合文档结构。<br>
**异常：** 不能仅凭扩展名信任文件；检测不确定、损坏或超过安全处理边界时停止，不将文件交给模型或渲染流程。

#### FR-M1-003 Office 结构读取工具（P0）

**逻辑能力名：** read_office_to_text(attachment_id)。<br>
**触发/前置：** 用户有权使用已上传附件，且 FR-M1-002 判定其格式可处理。<br>
**行为：** 返回带结构标识的文本或摘要。Excel 至少提供工作表名、单元格坐标、行列关系、必要的值/公式及已识别合并区域；Word 至少保留段落顺序、表格/单元格层次及必要标题关系。不能可靠提取的对象应标为未识别。本能力只读取和表达文件结构，不推断 Odoo 字段映射。<br>
**异常：** 无权附件、无内容、损坏文件或不可识别结构返回明确失败；不得声称完整读取未提取内容。

#### FR-M1-004 受控模板渲染工具（P0）

**逻辑能力名：** render_office_template(template_id, json_mapping)。<br>
**触发/前置：** 用户可访问模板；映射 JSON 已通过 FR-M1-007 校验；阻断性问题已消除。<br>
**行为：** 在模板副本上应用允许的映射，创建与原模板区分的新结果，不覆盖原件。所有预览和最终渲染均须执行结构、公式保护及回读校验；用户预览行为不得跳过或降低后端校验。AI 只能提交映射数据，不可提交或执行文件操作代码；用户和模型均不得指定任意服务器路径。<br>
**异常：** 映射格式不合法、目标不存在、写入不安全、模板容量不足、回读结果不一致或渲染失败时停止并返回诊断信息；不得交付部分文件作为成功结果。

#### FR-M1-005 Excel 完整性与公式保护（P0）

**触发/前置：** .xlsx 或 .xls 模板进入读取或渲染。<br>
**行为：** 对已声明支持且不与写入冲突的工作簿内容，应保留公式文本、样式、合并单元格和行列布局。公式单元格不得被映射值覆盖。每次渲染（包括用户预览）后端都必须回读输出并验证公式/结构保持和映射目标值；必须区分公式表达式和计算结果，本能力不承诺自行计算公式或刷新公式缓存。对于 .xls，其可处理对象及公式、样式保留边界必须基于代表性样本明确并验收；仅在声明支持范围内承诺保留。<br>
**异常：** .xlsm 不属于本期允许格式，不得创建或执行宏。复杂对象、公式或样式无法在声明范围内可靠保留时，拒绝处理并说明原因，不得静默损坏。公式缓存、外部链接、命名区域、受保护工作表及旧版 .xls 样式保留的测试策略见 OPEN-OFFICE-03。

#### FR-M1-006 Word 完整性保护（P0）

**触发/前置：** .docx 或 .doc 模板进入读取或渲染。<br>
**行为：** 对已声明支持且不与写入冲突的文档内容，应保留段落顺序、表格结构、样式及布局关系。.doc 的可处理对象和版式保留边界必须基于代表性样本明确并验收；若底层处理流程需要将 .doc 转换为 .docx，转换及回转过程不得破坏原有版式和待填内容/占位内容。<br>
**异常：** 页眉/页脚、图片、文本框、域、修订标记、嵌入对象和复杂分页未经能力验证不得承诺无损支持；无法可靠保留时拒绝处理或要求用户选择安全处理方式。转换后的结构或内容校验不通过时不得提供生成文件。

#### FR-M1-007 映射数据校验（P0）

**触发/前置：** 系统收到待读取结果或待渲染映射。<br>
**行为：** 校验映射必需结构、目标位置、值类型、允许的写入动作以及公式/结构保护规则。缺失、显式空值、类型错误和目标不存在必须可区分。<br>
**异常：** 缺失值不得默认为零、空字符串或其他业务值；不安全映射不得进入渲染，返回可理解的字段/位置级错误。

#### FR-M1-008 附件回传与失败状态（P0）

**触发/前置：** 文件渲染完成或任一处理步骤失败。<br>
**行为：** 成功时创建本次请求专属的新附件，提供给有权访问该聊天结果的用户下载；默认保留上传模板的原文件格式并在文件名中反映正确扩展名。若原格式无法可靠输出而需要升级为其他格式，系统必须在预览/确认阶段明确告知输入与输出格式差异及其影响，并取得用户确认后方可生成；不得静默转换。显示模板、结果文件名和处理状态。失败时区分格式/安全、读取、映射校验、渲染和附件交付失败。<br>
**异常：** 结果附件无法创建或授权时报告失败，不返回成功链接；不得复用另一请求的文件，也不得泄漏他人附件标识或下载能力。

#### FR-M1-009 生成文件回读校验（P0）

**触发/前置：** 任何 Office 渲染完成，包括用户预览、审核测试文件和最终交付文件。<br>
**行为：** 后端重新读取生成文件，验证文件可解析、必要结构/公式保持、映射目标值与已确认计划一致，并确认文件格式与用户上传格式相同，或符合用户已明确确认的格式升级选择。此校验是渲染成功、预览可见和附件交付的必要条件。<br>
**异常：** 回读失败、公式/结构被破坏或目标值不符时，将本次渲染标记为失败，不显示预览或提供下载；用户不得通过预览、确认或重试参数绕过校验。

### 5.2 Milestone 2：AI 映射与个人私有导出 Skill

#### FR-M2-001 模型与根记录准入（P0）

**触发/前置：** 用户请求将 Odoo 数据填入已读取模板。<br>
**行为：** 仅允许使用管理员策略准入的模型；确定模型和根记录，并向用户显示可核对的记录身份。模型准入、用户是否能访问记录、字段是否可提供给 AI 是独立判定。<br>
**异常：** 模型、记录或关联关系不在准入范围时拒绝；匹配为零条或多条时要求澄清，不得猜选。

#### FR-M2-002 当前用户授权数据读取（P0）

**触发/前置：** 根记录已唯一确认，模板分析指出必要数据类别。<br>
**行为：** 只能经 Odoo 权限网关读取填表所需字段和准入关联记录，网关按当前用户 ACL、记录规则、公司范围和字段权限校验；不得由 AI/工具直接查询数据库或绕过网关。提供给 AI 的值仅限安全白名单与当前用户权限的交集及当前映射所需范围。每次请求均重新读取实时数据，读取结果保留字段和记录来源以供计划校验及审计。<br>
**异常：** Odoo 权限网关、记录可见规则、公司边界、白名单或字段策略拒绝时停止相关读取并说明可处理范围；不得使用缓存/历史请求值替代实时读取，不得通过提升权限或模型自行选择未授权字段绕过限制。

#### FR-M2-003 AI 结构化映射计划（P0）

**触发/前置：** M1 模板结构和 M2 授权数据均已准备。<br>
**行为：** AI 只能基于 M1 模板结构和 Odoo 权限网关提供的本次授权数据提出结构化映射计划，至少标识目标位置、来源字段/记录、受限转换、必填性和重复明细处理建议。AI 不得直连 Odoo 数据库、业务模型或其他数据源。计划不得包含可执行代码或任意文件路径。<br>
**异常：** 位置、数据来源或业务含义不确定时标为待澄清；AI 不得发明记录值、编号、日期、金额或关系数据。模板指令不能改变系统权限或处理政策。

#### FR-M2-004 映射确认与歧义处理（P0）

**触发/前置：** 计划包含未确认映射、必填缺失或冲突。<br>
**行为：** 系统必须提供展示映射摘要、数据来源和未决项并由用户确认、补充明确值或取消的机制。首次映射默认在用户确认前不得渲染；任何未解决的必填歧义均不得渲染。M2 可读取和应用本用户的有效私有 Skill；命中后允许跳过 AI 映射推理，但仍须展示 Skill、模型和本次记录摘要并取得用户确认。已验证且匹配的 Skill 是否可进一步减少逐项确认由 OPEN-OFFICE-08 决策；在该事项决策前，按需要用户确认处理。不得静默应用失效或不匹配 Skill。<br>
**异常：** 未解决必填歧义、互斥说明或缺失数据时保持待澄清/失败且无输出文件。用户补充值标识为用户提供，不能伪装为 Odoo 来源。

#### FR-M2-005 根据记录生成文档（P0）

**触发/前置：** 根记录与必要字段权限有效，映射计划通过校验并满足确认规则。<br>
**行为：** 将授权数据转换为 M1 可接受的映射，在原模板副本上按 FR-M1-008 的格式规则生成文件；提供文件、根记录标识、模板标识及需人工检查事项。<br>
**异常：** 权限在请求期间变化、必填值为空、明细超出模板容量或源数据变化导致计划失效时，停止或要求重新确认；不得使用缓存/历史请求值，必须重新经 Odoo 权限网关取得最新数据。长耗时处理不得通过长时间持有业务记录锁来保证数据不变；交付前发现本次数据快照已不满足映射有效性时，丢弃输出并要求重新确认或生成。

#### FR-M2-006 私有导出 Skill 保存与复用（P0）

**触发/前置：** 用户对映射计划确认后，文件生成及回读校验成功；用户选择保存 Skill，或后续请求匹配到本人有效 Skill。<br>
**行为：** 用户可保存、修改、停用及复用本人私有导出 Skill。Skill 仅保存模板特征、适用模型和映射规则，不保存记录实际值、样例明文或文件内容。精确匹配时可跳过 AI 映射推理，但须按 FR-M2-004 展示命中摘要并取得确认；每次执行实时取数并重新验证权限和映射。修改后的 Skill 在再次成功生成前不得自动匹配。<br>
**异常：** 生成失败或用户未选择保存时不创建可用 Skill；非所有者不得查看或使用；无精确匹配、多重匹配、权限失效或规则校验失败时不得自动应用。

### 5.3 Milestone 3：Skill 生命周期

#### FR-M3-001 公共 Skill 发布、审核与生命周期（P0）

**触发/前置：** M2 私有 Skill 能力已交付；用户申请将私有 Skill 发布为公共版本，或公共 Skill 进入审核、发布、版本变更、停用/撤销流程。<br>
**行为：** 对公共 Skill 保存模板识别条件、映射规则、适用模型/字段范围和版本信息；公共版本不得保存某次记录的实际字段值、凭据或非必要附件内容。公共 Skill 的申请、审核和发布依 FR-PERM-001、FR-PERM-003 执行。每次应用都必须经 Odoo 权限网关实时拉取最新数据，不得复用历史请求数据。发布、变更、停用及撤销均有责任人和变更记录。<br>
**异常：** 无权发布、审核失败、模板不匹配或配置过期时不得启用；应用时按当前用户重新校验访问权；修改已发布 Skill 必须形成新版本并重新审核，不得静默改变已发布版本。


#### FR-PERM-001 私有 Skill 与公共 Skill 权限（P0）

**触发/前置：** 普通业务用户创建、修改 Skill，或申请将其共享给全公司。<br>
**行为：** 普通业务用户可在 M2 创建、修改和使用本人私有 Skill。只有系统管理员或明确获授发布权限的 Skill 审核员，在 M3 完成审核后才能将 Skill 发布为公司范围的公共 Skill。公共 Skill 的适用公司范围须明确；已发布 Skill 的修改形成新版本并重新审核。<br>
**异常：** 普通用户不得直接发布或修改公共版本；未获授权的用户不得通过界面、工具调用或更改请求参数绕过发布权限；无明确公司范围时拒绝发布。


#### FR-PERM-003 公共 Skill 审核闭环（P0）

**触发/前置：** Skill 所有者提交公共发布申请，申请已分配给具有审核授权的审核员。<br>
**行为：** 审核界面允许该审核员查看申请所需的原模板和 AI 生成的 Mapping Plan，并使用其本人有权访问的业务数据或经批准的测试数据生成测试文件；审核员可查看测试文件、记录验证结果，并批准或驳回及记录理由。审核员只能访问分配申请所需的材料。测试文件仅属于对应审核申请的材料，不得写入申请人或审核员的日常聊天；审核结束后的清理按 OPEN-OFFICE-13 决策执行。<br>
**异常：** 未分配申请、审核授权失效或所需数据不在审核员权限内时拒绝访问或生成；不得继承申请人的业务记录权限，不得展示无关聊天、附件或字段；审核未通过不得发布公共 Skill。


#### FR-PERM-004 私有 Skill 临时与预览附件隔离（P0）

**触发/前置：** 系统为私有 Skill 创建预览、测试或其他临时附件。<br>
**行为：** 临时及预览附件仅当前所有者和明确获授权的处理上下文可访问，并与该用户/私有 Skill 关联；附件下载能力须按当前用户权限重新校验。分配审核所需的附件仅能依据 FR-PERM-003 授予被分配审核员的有限访问。<br>
**异常：** 其他用户、未分配审核员或失效上下文请求附件时拒绝访问；不得生成可猜测的公开 URL，不得因附件 ID 可见而授予读取能力。

### 5.4 Milestone 4：企业级治理与审计

#### FR-M4-001 企业安全字段白名单治理（P0）

**触发/前置：** M1、M2、M3 已独立交付；企业管理员配置和维护 AI 数据准入策略。<br>
**行为：** 企业管理员能定义准入模型、版本化安全字段白名单、允许关联读取范围及禁止暴露的字段类型/敏感字段，并查看变更历史。字段只有同时列入白名单且当前用户有权读取时，才可用于 AI 提取、Mapping Plan 和生成流程；白名单不能替代当前用户 Odoo 权限。<br>
**异常：** 策略缺失、冲突或无效时默认拒绝相关模型/字段；普通业务用户不得扩大白名单；策略变更须留下责任人、时间、变更前后版本和理由，且不得回溯扩大已生成结果的访问范围。


#### FR-PERM-002 安全字段白名单执行约束（M2 起强制，P0）

**触发/前置：** M2/M3 中 AI 为业务映射、Skill 创建或 Skill 应用读取 Odoo 模型/字段信息。<br>
**行为：** 从 M2 起，字段只有同时存在于当前安全字段白名单且当前用户具有该记录和字段读取权限时，才可由 Odoo 权限网关提供给 AI。M2 部署使用安装初始化数据或部署配置提供最小、经批准且非敏感的基线字段集合，足以覆盖该部署的代表性验收场景；此阶段不提供白名单管理界面、任意增删改和企业级版本治理。M4 提供该白名单的企业级配置、版本和审计能力。关联模型及字段逐层适用同一规则；白名单默认拒绝，必须排除凭据、密码、薪资和不相关客户隐私等敏感内容。<br>
**异常：** 白名单缺失、字段未列入、当前用户无权访问或字段敏感级别未知时，不向模型、Mapping Plan、聊天回复或审核测试文件提供该字段值；不得由用户或模型自行扩展白名单。M2 基线初始化或部署配置未提供有效白名单时，字段访问默认拒绝，不能以硬编码字段作为回退。


#### FR-M4-002 企业审计与治理追溯（P0）

**触发/前置：** 发生数据策略/白名单变更、Skill 提交/审核/发布/撤销、文档生成或访问控制决策。<br>
**行为：** 系统记录可关联的操作者、时间、请求/线程标识、策略与 Skill 版本、审核结果及理由、处理阶段和输出附件授权结果；审计记录不得包含不必要的业务字段值或凭据，且仅授权治理角色可查询。<br>
**异常：** 关键审计记录无法保存时，策略发布、Skill 公共发布及文档交付等受审计保护的操作不得报告成功；不得以普通业务日志替代审计记录。


## 6 业务规则

| 编号 | 规则 |
|---|---|
| BR-OFFICE-01 | 业务事实只能来自当前用户获授权的 Odoo 数据，或由用户明确补充并确认的数据；模型不得编造事实。 |
| BR-OFFICE-02 | 文件处理只接受经系统格式和结构校验的文件；扩展名本身不是安全证据。 |
| BR-OFFICE-03 | 模板原件不得被输出结果覆盖；生成文件是新结果，不代表审批、签署或对外提交。 |
| BR-OFFICE-04 | Excel 公式目标不得被普通映射覆盖；系统不得声称计算或刷新公式结果。 |
| BR-OFFICE-05 | 业务数据读取始终受当前用户权限约束；模型/字段准入是额外限制，不是权限替代。 |
| BR-OFFICE-06 | 模板文本和模型生成映射均为不可信输入，不能改变访问范围、文件限制或系统策略。 |
| BR-OFFICE-07 | 生成流程对 Odoo 业务记录只读，不得创建、修改、删除、审批、签署或发送记录。 |
| BR-OFFICE-08 | 必填数据缺失、记录不唯一、目标位置不明确或映射冲突时必须澄清、拒绝或无文件结束，不得猜测。 |
| BR-OFFICE-09 | Skill 是可验证映射配置，不是权限凭证；每次执行均重新校验文件匹配、策略和当前用户权限。 |
| BR-OFFICE-10 | 任何阶段失败均不得返回伪成功、部分损坏文件或其他请求的历史文件。 |
| BR-OFFICE-11 | 普通用户创建的 Skill 默认为本人私有；转为公司公共 Skill 必须经过有发布权限的审核角色批准。 |
| BR-OFFICE-12 | AI 可见字段必须同时满足管理员维护的安全字段白名单和当前用户对具体记录/字段的读取权限；任一条件不满足即拒绝暴露。 |
| BR-OFFICE-13 | 公共 Skill 审核只向被分配的审核员开放该申请所需材料；审核员不继承申请人的业务记录权限。 |
| BR-OFFICE-14 | 私有 Skill 的临时、预览和测试附件按所有者隔离；明确分配的审核访问仅限申请所需附件和处理目的。 |
| BR-OFFICE-15 | Office 结构、公式保护和生成文件回读校验由后端强制执行；预览、审核测试和最终交付不得豁免。 |
| BR-OFFICE-16 | Skill 仅保存执行规则和映射配置，不得存储业务数据；每次执行须通过 Odoo 权限网关实时读取最新数据。 |

## 7 业务状态

### 7.1 状态定义

| 状态 | 业务含义 |
|---|---|
| 已接收 | 请求和附件已关联，等待格式/权限检查 |
| 检查中 | 系统检查文件结构、记录身份和准入策略 |
| 待澄清 | 必需数据、记录身份或映射歧义等待用户处理 |
| 待确认 | 映射计划已形成，等待用户/授权角色确认 |
| 处理中 | 已满足必要确认条件，正在渲染并验证输出 |
| 已生成 | 本次新附件保存成功并可由授权用户取得 |
| 失败 | 请求未生成可验证输出，原因已反馈 |
| 已取消 | 用户取消未完成请求，未交付生成文件 |

### 7.2 状态流转

| 当前状态 | 条件 | 目标状态 |
|---|---|---|
| 已接收 | 文件、附件权限检查通过 | 检查中 |
| 已接收/检查中 | 文件、记录或策略不满足 | 失败 |
| 检查中 | 信息有歧义或需用户决策 | 待澄清 |
| 检查中 | 映射计划完成 | 待确认 |
| 待澄清 | 用户补充并通过校验 | 检查中/待确认 |
| 待确认 | 用户确认映射 | 处理中 |
| 待确认 | 用户拒绝或取消 | 已取消 |
| 处理中 | 生成和交付成功 | 已生成 |
| 处理中 | 任一必要步骤失败 | 失败 |

### 7.3 禁止状态

- 必需映射未解决或未满足确认规则时不得进入处理中。
- 未通过文件完整性和附件访问检查时不得进入已生成。
- 业务记录有写入副作用的结果不得作为本需求的成功结果。

### 7.4 Skill 生命周期状态

| 状态 | 业务含义 | 允许的主要动作 |
|---|---|---|
| 私有草稿 | 所有者可见、尚未申请公共发布的 Skill | 所有者创建/修改/验证/删除；不得被其他普通用户发现或应用 |
| 待审核 | 所有者已提交公共发布申请 | 所有者可撤回；被分配审核员可查看申请材料、生成审核测试文件、批准或驳回 |
| 已驳回 | 审核未通过，Skill 仍为私有 | 所有者查看审核意见、修改后重新提交；不得作为公共 Skill 使用 |
| 公司公共 | 审核通过并在明确公司范围内发布的不可变版本 | 授权范围内用户可按当前权限应用；修改必须创建新版本并重新审核 |
| 已停用/已撤销 | 不再允许新请求应用的 Skill 版本 | 管理员或有权审核角色停用/撤销并记录原因；该版本不可原位恢复，可克隆为新的私有草稿并重新验证/审核；历史结果权限不因此扩大 |

状态流转为“私有草稿 → 待审核 → 公司公共 / 已驳回”；已驳回可回到私有草稿后重新申请；已发布版本可被停用或撤销。已停用/已撤销版本为终态，不得原位重新启用；所有者或授权管理员可克隆为新的私有草稿，重新验证并按要求审核，历史版本和关联关系须保留。具体审核分配、撤回窗口和历史版本保留策略见 OPEN-OFFICE-09。

## 附录 D 技术架构建议（非规范性）

建议按四阶段保持职责分层：M1 负责 Office 结构读取、受控渲染及每次预览/交付后的回读校验；M2 由 Odoo 权限网关按当前用户实时取数，AI 仅消费获准的结构化输入并提出 Mapping Plan；M3 保存不含业务值的 Skill 规则并管理私有/公共审核生命周期；M4 管理企业字段白名单、授权策略版本和审计追溯。AI 不直连业务数据源；预览与最终交付共用后端强制验证。

已存在的工具框架可用于暴露受约束的读取/渲染能力；独立 Addon 能否完全覆盖聊天 Office 拒绝逻辑及所需扩展点，需通过后续技术验证确认。不得在没有 Spike 证据前承诺具体 Office 库、无损格式范围或运行性能。
