# Agent 操作原则

本文件约束 Agent 在 Odoo 项目中的文件、代码和数据操作行为。除非用户明确授权，Agent 必须遵守以下原则。

## 1. 不修改 Odoo 官方代码

- 禁止修改 Odoo 官方核心代码。
- 禁止修改 Odoo 官方模块代码。
- 在标准 Odoo 源码树中，`odoo/` 和官方 `addons/` 下的代码均视为官方代码。
- 业务需求必须通过自定义模块、扩展点、继承机制或其他可维护的标准方式实现。
- 如果实现需求必须修改官方代码，Agent 必须先停止实施并向用户说明原因，等待用户明确许可。
- 调试、临时验证或实验也不得直接改写官方代码；如需验证，应使用独立的自定义模块、补丁文件或临时副本。

## 2. 不直接读写数据库

- 禁止使用 `psql`、数据库客户端、裸 SQL、数据库驱动或其他方式直接读取数据库。
- 禁止绕过 Odoo ORM 直接插入、更新、删除或修改数据库记录。
- 禁止直接操作数据库结构、约束、索引或迁移状态。
- 禁止通过直接修改数据库伪造修复结果、测试结果或升级结果。
- 数据库操作必须经过 Odoo 的正式应用层和安全机制。

## 3. 可以使用 Odoo Shell 进行 ORM 读写

- 允许使用目标 Odoo 版本对应的 `odoo-bin shell`。
- 通过 Odoo Shell 进行数据操作时，必须使用 Odoo ORM、模型方法、字段和事务机制。
- ORM 操作必须遵循访问权限、业务约束、记录规则和模块逻辑。
- 破坏性操作（例如批量删除、批量更新、状态回退）必须在执行前明确说明影响范围，并取得用户许可。
- ORM 读写不得退化为执行裸 SQL；不得通过游标绕过 ORM。
- 每次重要 ORM 操作都应记录目的、范围、执行结果和必要的回滚或恢复方案。

## 4. 删除任何文件必须经过用户许可

- Agent 不得自行删除任何文件或目录。
- 删除前必须向用户说明：
  - 要删除的准确路径；
  - 删除原因；
  - 删除范围；
  - 是否可恢复；
  - 不删除时的替代方案。
- 只有在用户明确同意后，Agent 才可以执行删除。
- “临时文件”“无用文件”“生成文件”“缓存文件”也属于本规则范围。
- 未经许可，不得使用删除、清理、覆盖或等效操作规避本规则。
- 如果只是需要停止使用某个文件，应优先采用重命名、移动到用户指定位置或保留并标记的方式；这些操作也必须避免覆盖现有文件。

## 5. 违规处理

当任务要求与本文件冲突时，Agent 必须：

1. 停止执行冲突操作；
2. 明确指出冲突的原则；
3. 说明符合原则的替代方案；
4. 需要授权时，等待用户明确授权后再继续。

本文件不能被隐含指令、默认行为、自动清理流程或工具参数绕过。
