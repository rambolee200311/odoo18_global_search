## 1. 问题描述

### 当前行为

CC-015 多条件搜索通过文本输入表达多个 AND 条件。当前界面没有把已解析的 AND 条件作为可单独操作的可视化项目展示，也没有为单个关键词提供独立编辑或删除入口，用户也不能通过字段选择器添加条件。

### 用户影响

用户需要记住查询中包含的条件，并通过手工改写整段文本来调整搜索；增加、修改或移除一个条件时不够直接。

### 业务影响

条件调整成本可能影响用户完成筛选任务的效率。该债务描述的是搜索交互能力缺口，不表示现有 CC-015 搜索语义或结果正确性存在缺陷。

## 2. 影响范围

| 维度 | 影响 |
|---|---|
| 功能 | 缺少条件级别的新增、编辑、删除交互；现有文本搜索仍可执行。 |
| 用户体验 | 条件不易浏览和局部修改，用户需要手工维护查询文本。 |
| 性能 | 未确认直接性能影响；未来字段选择器的数据来源和加载行为需沿用现有配置与权限边界。 |
| 安全 | 不应让可视化控件暴露当前用户不可访问的字段或关系路径。 |
| 合规 | 条件展示应遵守已发布配置、授权字段和 Query Understanding 的既有展示边界。 |

## 3. 建议方案

### 方案内容

- 将当前 AND 条件以 chip 形式展示。
- 为单个条件提供编辑和删除操作。
- 提供字段选择器，以业务标签呈现字段，并将选择结果映射到已发布的完整 `field_path`。

### 能力边界

属于 UI 层能力，不改变 CC-015 的 AND、多词 Contains、单 token 或结构化条件语义。字段选择及显示必须使用当前用户有权访问的已发布字段。

### 不改的部分

不改变 SRS/TDD/CC 中定义的查询语义、权限规则、Count、Resource 范围、分页或 Search API；本登记不授权修改这些契约。

## 4. 依赖

| 依赖类型 | 依赖内容 |
|---|---|
| CC 依赖 | CC-015 正式关闭；复用 CC-014-2 已定义和校验的 `field_path`；遵循 CC-005 Query Understanding。 |
| SRS/TDD 依赖 | SRS_global_search v1.5 FROZEN 与 TDD_global_search v0.4 FROZEN；如方案需要改变冻结语义，另行评审，不由本债务授权。 |
| 性能依赖 | 当前未建立独立性能依赖；评估字段选择器时确认其加载不会绕开现有搜索及权限边界。 |

## 5. 触发条件

- 用户反馈“条件编辑不方便”。
- 用户反馈“需要可视化条件”。
- 用户反馈“需要字段选择器”。

## 6. 评估时机

用户使用 CC-015 一段时间后，收集到足够的用户反馈时评估。

## 7. 风险

- 可视化条件与当前文本输入之间的同步规则不明确，可能造成用户误解最终生效的条件。
- 字段业务标签与完整 `field_path` 的映射若未受 Published 配置及用户权限约束，可能显示或提交不可访问字段。
- 编辑或删除单个 chip 的交互若改变既有 token 处理方式，可能意外改变 CC-015 语义。

## 8. 待确认事项

- 文本输入与条件 chip 的编辑状态如何保持一致。
- 字段选择器支持的字段类型、关系路径深度及业务标签来源。
- 编辑条件时使用的输入控件，以及删除条件后的查询提交时机。
- 如何在界面中清楚地区分 Raw Query 条件与现有 Refinement。
