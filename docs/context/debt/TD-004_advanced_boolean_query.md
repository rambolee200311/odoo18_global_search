## 1. 问题描述

### 当前行为

CC-015 多条件自由文本查询支持 AND 语义，不支持 OR、NOT 或括号组合；不支持的布尔表达式会被拒绝，不作为部分条件执行。

### 用户影响

用户不能用一个查询表达“订单号或客户名”等 OR 关系，也不能表达“符合条件但排除异常项”等 NOT 关系或更复杂的分组。

### 业务影响

需要组合替代条件的查询无法通过当前自由文本语法直接表达，用户可能需要拆分为多个搜索或手动调整条件。此登记不是对当前 AND 搜索正确性的否定。

## 2. 影响范围

| 维度 | 影响 |
|---|---|
| 功能 | 自由文本条件组合仅覆盖当前 AND 能力。 |
| 用户体验 | 复杂查询需要拆分或重复操作。 |
| 性能 | 布尔分支及嵌套表达可能扩大查询域和 Count 工作量；当前未评估。 |
| 安全 | 新增语法必须继续使用受限解析和服务端权限校验，不得接受客户端 ORM domain 或可执行表达式。 |
| 合规 | Query Understanding、错误处理及日志仍需遵守现有契约，不能泄露原始条件或未授权字段。 |

## 3. 建议方案

### 方案内容

将 OR、NOT 和括号作为一个查询语言能力整体进行设计，明确形式语法、运算优先级，以及布尔表达式与 Refinement 的组合规则。

### 能力边界

属于查询语言能力，会改变 CC-015 当前 AND-only 语义，必须按契约修订处理，而不是作为实现优化。

### 不改的部分

本债务登记不定义具体语法、优先级或执行方式，不修改 CC-015，也不授权绕过 SRS/TDD 的正式变更评审。

## 4. 依赖

| 依赖类型 | 依赖内容 |
|---|---|
| CC 依赖 | CC-015、CC-016、CC-017 正式关闭；CC-015 语义变更须完成正式变更评审。当前 CC-015 尚未正式关闭，该依赖目前未满足。 |
| SRS/TDD 依赖 | SRS 与 TDD 的正式变更评审通过后，方可定义改变现行语义的查询语言。 |
| 性能依赖 | 设计时需评估布尔表达式对查询计划、精确 Count 和现有性能边界的影响；当前没有测量结论。 |

## 5. 触发条件

- 用户反馈“需要 OR”。
- 用户反馈“需要 NOT”。
- 用户反馈“需要括号”。
- 用户反馈“AND 不够用”。

## 6. 评估时机

用户使用 CC-015 至 CC-017 一段时间并收集到足够反馈后，且完成 SRS、TDD 和 CC-015 变更评审后评估。

## 7. 风险

- 若不明确定义语法和优先级，不同用户对相同查询的解释可能不一致。
- NOT 与权限、Resource 范围、空值及 Refinement 组合时可能造成结果范围误解。
- 布尔表达式可能改变精确 Count、分页、Query Understanding 和失败处理的行为。
- 新解析器若接受可执行 domain 或绕开服务端权限边界，会引入安全风险。

## 8. 待确认事项

- 运算符大小写、分隔符和转义规则。
- OR、NOT 和括号的优先级及嵌套边界。
- 布尔表达式与结构化条件、Refinement 及多 Resource 搜索的组合方式。
- 语法错误、空分支和否定条件的错误及 Count 语义。
