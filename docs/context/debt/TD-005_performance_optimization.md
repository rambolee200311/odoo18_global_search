## 1. 问题描述

### 当前行为

多 token 搜索可能需要为多个 token 构建并执行条件；跨多个 Resource 或多个可搜索字段时，执行工作也可能增加。Contains 查询在某些数据和索引条件下可能产生较重的查询计划。

目前这些是待评估的性能风险，不代表已经通过测量确认存在响应超标、重复查询或全表扫描。

### 用户影响

若实际查询计划或数据规模导致耗时增加，用户可能感受到搜索或 Count 响应变慢。

### 业务影响

搜索延迟或 Count 延迟若达到不可接受程度，可能影响依赖快速检索的日常业务流程。当前尚无证据量化该影响。

## 2. 影响范围

| 维度 | 影响 |
|---|---|
| 功能 | 性能下降可能延迟搜索、Count 或结果展示；未确认功能正确性缺陷。 |
| 用户体验 | 搜索响应慢可能降低筛选效率。 |
| 性能 | 关注多 token、多 Resource、多字段 Contains、查询计划和精确 Count 的实际成本。 |
| 安全 | 优化不得绕过当前用户权限、Record Rules、字段授权或失败关闭边界。 |
| 合规 | 必须遵守 CC-006 索引规则及现有精确 Count 要求；不得通过降低准确性掩盖延迟。 |

## 3. 建议方案

### 方案内容

先建立可复核的性能基线并检查查询计划，再依据实测证据评估索引或查询改造。

### 能力边界

属于性能层，不改变 CC-015 查询语义。优化须遵守 CC-006 索引规则，并保持既有精确 Count、权限和结果身份要求。

### 不改的部分

本登记不提出具体索引变更、SQL/ORM 改造、缓存方式或性能目标数值；不授权实施优化。

## 5. 触发条件

- 性能基线显示搜索响应时间超出适用的既有预算。
- 查询计划显示不期望的全表扫描。
- 用户反馈“搜索太慢”。

## 6. 评估时机

CC-015 至 CC-017 关闭后，性能基线和查询计划建立并收集到足够性能数据时评估。

## 7. 风险

- 索引可能增加存储和写入维护成本；是否值得采用需由实测确认。
- 查询改造可能影响精确 Count、Result Identity、分页或权限过滤。
- 单一测试环境或不具代表性的数据分布可能导致错误优化结论。
- 全表扫描的观察需结合实际数据规模与查询成本判断，不能单独视为已证实的用户影响。

## 8. 待确认事项

- 代表性数据规模、Resource 组合、查询形态和并发负载。
- 适用的现有性能预算及采集环境。
- 查询计划及性能证据的复核方式。
- 任何索引变更与 CC-006 规则的适用性。
