## 1. 问题描述

### 当前行为

当前多条件搜索不提供条件建议。用户无法从界面获知可添加哪些条件、某个条件是否适用于当前搜索，或某个条件可能如何缩小结果范围。

### 用户影响

用户得到较多结果时，可能不清楚如何进一步缩小范围；可能需要反复尝试不同条件。

### 业务影响

缺少引导可能增加完成筛选任务所需的交互次数。建议条件及其预计收窄数尚未定义或测量。

## 2. 影响范围

| 维度 | 影响 |
|---|---|
| 功能 | 缺少搜索后的建议条件及用户主动添加建议的入口。 |
| 用户体验 | 用户可能不知道如何收窄结果，也难以判断建议是否适用。 |
| 性能 | 若计算建议及预计收窄数需要额外查询，可能增加搜索和 Count 开销；当前未测量。 |
| 安全 | 建议只能基于当前用户获准访问的字段和数据生成，不应暴露隐藏字段或记录信息。 |
| 合规 | 预计结果数可能与现有精确 Count 契约冲突；建议交互需遵守已批准的 Count 和权限边界。 |

## 3. 建议方案

### 方案内容

后续评估可研究在搜索后展示建议条件及每项建议的预计收窄数，并允许用户点击建议添加条件。

### 能力边界

涉及 UI 层和性能层，不改变 CC-015 查询语义。建议条件必须保持显式、可选择，不应静默改变用户当前查询。

### 不改的部分

本登记不定义建议算法、预计收窄数的计算方式、排序规则或性能实现；不授权引入与精确 Count 契约冲突的估算结果。

## 5. 触发条件

- 用户反馈“不知道加什么条件”。
- 用户反馈“需要条件建议”。
- 已具备真实搜索数据和性能证据，可用于评估建议价值及成本。

## 6. 评估时机

CC-015 至 CC-019 关闭后，真实搜索数据和性能证据已收集，且确认不与 Count 契约冲突时评估。

## 7. 风险

- 计算条件建议及预计收窄数可能增加查询开销，影响搜索响应时间或 Count。
- 预计收窄数的计算方式若不清晰，可能被用户误认为精确 Count。
- 建议若未经过当前用户权限过滤，可能暴露不可访问字段或数据特征。
- 建议过多、相关性不足或无法解释时，可能增加 UI 复杂度并降低可用性。

## 8. 待确认事项

- 条件建议的来源、生成规则及适用条件。
- 预计收窄数是精确值还是其他指标，以及如何与 Count 明确区分。
- 建议字段、顺序和展示数量的确定方式。
- 如何确保建议生成和用户添加过程遵守权限、Published 配置及性能约束。
