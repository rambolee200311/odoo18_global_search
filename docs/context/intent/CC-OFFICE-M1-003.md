## 1. 变更概述

Phase 4 将在 Odoo 中持久化请求状态并交付经回读验证的结果附件。TDD 明确指出，`ir.attachment` 可能在 ORM 操作中触发 filestore I/O，事务回滚不等于外部文件系统副作用已回滚。此 Spike 先验证存储和清理边界；它不实现请求模型或产品附件流程。

## 3. 范围冻结

### 3.1 在范围内

- 在当前已批准的 Odoo 18 开发环境中，通过项目约定的 `./venv/bin/python odoo-bin shell -c odoo.conf -d odoo18ce` 执行受控验证；不建立隔离数据库。
- 运行前记录 Odoo commit/version、Python、PostgreSQL 版本、配置的 filestore 位置（报告中脱敏）及执行用户的必要权限信息。
- 使用唯一、可识别的合成文件与测试标记；不读取、修改或删除真实业务附件。
- 验证合成附件的 ORM 创建、授权用户读取、文件内容一致性、ORM 删除及重复清理行为。
- 通过独立事务/游标观察成功提交与显式回滚结果；禁止 `sudo()` 扩大源附件权限，禁止手动 `commit` 后继续使用旧 env/recordset。
- 仅对本次生成的合成附件，记录 Odoo 返回的存储标识，并以只读方式观测关联 filestore 对象的存在/消失；不得直接删除未知路径或扫描/清理无关对象。
- 验证回滚/删除后的数据库记录与存储对象关系、访问授权和失败输出不可访问性；对无法安全清理的孤儿对象，提出官方 API 可支持的补偿方案或单独定时清理方案（本 Spike 不实现清理任务）。
- 形成带运行命令、版本快照、脱敏日志摘要、测试标记/记录 ID、事务结果和清理结论的 Spike 报告。

### 3.2 超出范围

- 创建正式 Office 请求模型、字段、SQL constraint、`request_uuid`、产品附件记录或用户界面。
- 修改 Odoo 官方源码/Addon、`ir.attachment` 实现、配置文件、数据库 schema 或既有业务记录。
- 安装/升级依赖、模块、Queue Job 或建立隔离数据库。
- 访问或修改真实业务附件，批量遍历/删除 filestore 内容，直接对非本次生成的磁盘路径执行删除。
- 实现定时清理、重试、异步调度、业务恢复、聊天 Provider 路由或结果下载功能。
- 把 Spike 结果描述成产品级 ACL/并发/容量通过或生产环境认证。

### 3.3 非目标

- 证明所有存储后端、所有公司/用户组或生产部署的行为一致。
- 用 Queue Job 规避事务、权限或 filestore 风险。
- 在没有证据时把 ORM 回滚推定为文件存储回滚。

## 4. 允许操作与环境边界

| 类别 | 约束 |
|---|---|
| Odoo 环境 | 仅使用现有 `odoo18ce` 开发数据库和项目 `venv`；不创建隔离库、不切换到未授权 DB |
| 调用方式 | 通过项目指定的 `odoo-bin shell -c odoo.conf -d odoo18ce`；不得直接连接 PostgreSQL 绕过 ORM 获取/修改数据 |
| 测试数据 | 仅使用合成数据和唯一标记；开始前盘点相同标记，结束后再次盘点并清理本 Spike 新建记录 |
| 权限 | 当前 Odoo 用户权限执行源读取；不得通过 `sudo()` 绕过 ACL/Record Rules。任何需要管理员准备的合成对象必须清晰隔离并记录授权路径 |
| 文件系统 | 只读观察本次合成附件对应的 filestore 对象；只通过 Odoo ORM/API 清理数据库附件；禁止直接删不确定对象 |
| 事务 | 用可重建的新 cursor/env 验证事务结果；不在显式提交/回滚后复用失效环境对象 |
| 数据保护 | 日志不记录附件原文、客户信息、密钥、绝对路径或不必要的用户数据；只记录合成标记、稳定错误类型和经脱敏的存储证据 |

若测试必须扩大到不同权限主体，但当前开发实例没有可用、经批准的测试身份，暂停该场景并将证据缺口标为 BLOCKED；不得自行创建真实用户或改变现有用户权限。

## 5. 必需验证行为

| ID | 验证行为 | 预期观察 |
|---|---|---|
| CC-CHANGE-001 | 建立可重复的测试前/后盘点方法 | 能用唯一标记识别本次附件记录；盘点结果不包含业务附件内容 |
| CC-CHANGE-002 | 通过 ORM 创建并提交合成附件，读取并校验字节 | 提交后新 cursor 能找到记录；有权测试用户可读取精确合成字节；filestore 行为被记录 |
| CC-CHANGE-003 | 在独立事务中创建合成附件后显式回滚 | 新 cursor 的 ORM 查询结果与 filestore 对象状态均有实测记录；不凭推测认定二者同步回滚 |
| CC-CHANGE-004 | 通过 ORM 删除已提交合成附件并重复执行受控清理 | 数据记录删除/不可见，相关存储副作用可观察；重复清理不会损伤其他记录或对象 |
| CC-CHANGE-005 | 验证权限、失败输出和事务外快照设计所需证据 | 无权主体不能读取受限合成附件；失败/回滚场景不形成可访问的结果附件；指出附件内容读取能否脱离长事务安全完成 |
| CC-CHANGE-006 | 对观测到或无法排除的 filestore 孤儿给出补偿路径 | 优先给出有 Odoo API 支持且经实测的处理方式；若不支持，提出独立清理任务方案、识别条件、误删防护和审计要求，明确该方案尚未实现/验证 |

Spike 不得伪造“短事务成功”结论。若 Odoo 附件存储调用本身执行外部 I/O，应如实记录该调用与数据库事务的边界，并将结果交由 Phase 4 TDD/CC 评审。

## 9. 停止条件 / 升级闸门

| 触发条件 | 处置 |
|---|---|
| 测试标记与已有业务数据冲突、无法证明对象属于本 Spike | 立即停止；不读取/修改/清理该对象；记录脱敏证据并请负责人处置 |
| 需要创建隔离数据库、修改 Odoo 配置、安装模块/依赖或改数据库 schema | 停止；当前 CC 不授权这些操作，提交新 CC/授权 |
| 无法用当前用户权限验证，必须使用 `sudo()` 才能通过 | 记录权限缺口；不绕过 ACL；升级 TDD/权限设计 |
| 回滚/删除后存在孤儿对象且无法通过受支持 API 安全识别和清理 | 停止 Spike 并阻塞 Phase 4；提出技术方案，由 TDD/CC 另行批准 |
| 附件文件 I/O 与长事务不可分离，或发生不可接受的锁占用 | 停止 Phase 4 设计；提交事务边界证据及 TDD 修订问题，不以 Queue Job 规避 |
| 出现非合成业务记录变更或无法清理本次合成记录 | 立即停止后续步骤，保护现场，报告负责人；不扩大补偿操作 |
| 证据不完整、运行命令/环境与批准范围不符 | 结果标记 BLOCKED/NOT RUN，不得宣称 Spike PASS |

## 10. 完成定义 / Phase 4 Gate

1. `CC-TEST-001—008` 均有实际运行状态、命令、版本与当前环境证据；不得以设计推断代替运行结果。
2. 报告覆盖成功提交、显式失败/回滚、ORM 删除、重复清理、权限边界、文件存储副作用和测试数据清理。
3. 仅操作本次合成附件；无未处理合成记录、无未授权数据库或配置变更；若有存储孤儿，明确对象识别与经批准的补偿责任。
4. 明确短事务 A/B 和附件文件 I/O 的可行性；无法证实时按 BLOCKED 处理并说明 Phase 4 阻塞原因。
5. 对观察到或无法排除的孤儿存储，报告必须提出官方 API 支持的补偿路径或单独定时清理方案；该清理方案的实现不属于本 CC。
6. 形成可审阅的 Spike 报告、脱敏日志摘要、环境快照及清理核对记录，并由负责人评审结论。
7. **只有全部关键门禁通过且证据完整，才可建议 Phase 4 CC 起草/实施；Spike PASS 本身不授权 Phase 4。**
