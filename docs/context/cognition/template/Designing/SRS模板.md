## 0 文档说明

### 0.1 本文档回答什么、不回答什么

**回答「做什么（WHAT）」与「为什么做（WHY）」：**

- 业务目标、业务范围、功能需求、业务规则、业务状态生命周期、验收标准
- 配置项及其**业务含义与默认值**（配置本身是需求，不是技术实现）

**不回答「怎么做（HOW）」——以下全部属于 DDD / TDD 范畴，本文档禁止定义：**

| 禁止出现在 SRS 的内容 | 归属 |
|---|---|
| 具体技术栈、框架版本、数据库选型 | TDD |
| 模型字段类型、数据库表结构、索引、约束 SQL | TDD |
| 异步队列机制、worker 实现、cron 巡检间隔与实现 | TDD |
| 锁机制（行锁 / 分布式锁）、事务边界、重试计数实现 | TDD |
| 具体 API 调用方式、报文格式、SDK 用法 | TDD |
| 页面路由、组件库、前端框架选型 | TDD |
| `ir.model.access.csv`、`res.groups`、record rule、ACL | TDD |
| 具体的依赖模块 `depends` 清单 | TDD（manifest） |

> **判定口诀：** 凡是包含具体技术名词（队列名、锁、cron、ORM、表名、字段类型）的表述，都应移出 SRS。SRS 只描述「系统在业务上必须表现出什么」。

### 0.2 冻结与变更规则

- **冻结后只做勘误**：修正文档漂移、歧义澄清、错别字；**不新增业务需求**
- 冻结版本文件**不覆盖、不删除**，新增勘误版本（如 v1.3.4），历史版本保留为归档
- 新增业务需求 → 走**下一版本**（如 v1.4.0），不回溯修改已冻结版本
- **业务冻结 ≠ 技术冻结**：单纯的技术方案调整**不得**修改已冻结的 SRS；若 DDD/TDD 阶段发现 SRS 存在业务矛盾、遗漏或不可满足的业务约束，必须发起**需求勘误 / 需求变更**处理，**技术设计不得自行改变业务语义**（详见附录 B）

### 0.3 编号规则

- **永久编号、不回收**：删除或放弃的需求保留编号并标注「已废弃」，后续新增不复用旧号
- 格式：`{类型}-{域}-{序号}`，例如 `FR-IMPORT-01`、`BR-ORDER-03`
- 编号在创建时分配，全文档唯一，**冻结后不再重排**
- **编号适用范围：** `ROLE / FR / BR / CFG / NFR` 统一使用 `{类型}-{域}-{序号}`；`AC`、`BD` 使用**文档级连续编号**（`AC-01`、`BD-01`），不冠域名——AC 与 BD 是整份文档的验收案例 / 决策记录，全局连续更简洁。若组织偏好统一，也可写成 `AC-{域}-01`，但须在全文档保持一致。

| 前缀 | 含义 | 编号格式 | 所在章节 |
|---|---|---|---|
| FR | 功能需求（Functional Requirement） | `{域}-NN` | 第 5 章 |
| BR | 业务规则（Business Rule） | `{域}-NN` | 第 6 章 |
| ROLE | 角色与权限 | `{域}-NN` | 第 4 章 |
| CFG | 配置需求 | `{域}-NN` | 第 8 章 |
| NFR | 非功能需求 | `{域}-NN` | 第 10 章 |
| AC | 验收标准 | 文档级 `NN` | 第 11 章 |
| BD | 业务决策记录 | 文档级 `NN` | 附录 B |

### 0.4 规范措辞

- **必须 / 禁止 / 不得**：强制性业务要求，不满足即视为需求未实现
- **应 / 不应**：原则性要求；若无法满足，必须有明确理由并经评审确认
- **可 / 允许**：描述业务上被允许的行为或可执行的**能力**；一旦写入 FR/BR，仍属于正式需求，不得理解为「可选实现」
- **支持**：本身不表示约束强弱，须与「必须 / 应 / 可」组合使用（如「必须支持批量导入」）
- **建议 / 推荐**：非规范性说明，不应单独形成 FR/BR，也不作为验收依据
- **总原则：凡进入 FR / BR / ROLE / CFG / NFR 编号体系的条目，均为正式契约，必须实现并验收**
- 每条需求必须可测试、可判定，禁止使用「友好地」「合理地」「快速地」等模糊表述

### 0.5 单一事实来源（SSOT）

> **同一业务事实只允许在一个章节正式定义，其他章节只通过编号引用，不复制规则正文。** 这是避免大型 SRS 文档漂移的核心规则。

| 业务事实 | 唯一定义位置 |
|---|---|
| 角色与权限 | 第 4 章 |
| 业务规则（含阻断规则） | 第 6 章 BR 表 |
| 状态含义 | 7.1 |
| 状态流转 / 禁止流转 | 7.2 / 7.3 |
| 配置默认值 | 第 8 章 |
| 验收标准 | 第 11 章 |

> 例：阻断规则只在第 6 章 BR 表中定义，第 11 章通过 `BR-{域}-XX` 引用，不在两处各写一遍正文。历史上曾考虑为「阻断规则汇总」单独设节，现已按 SSOT 原则取消，阻断规则以 BR 表为唯一事实来源。

### 6.1 业务异常 vs 基础设施异常

> **填写说明：** 显式区分两类异常的处理策略，这是需求工程的关键边界。**SRS 只定义业务层可感知的异常类别及其业务处理结果**；HTTP 状态码（401/429）、数据库死锁、网络异常类型、队列崩溃等具体技术错误映射属于 TDD。

| 类型 | 含义 | 业务处理 |
|---|---|---|
| **业务异常** | 输入不合法、规则不满足、匹配失败等**业务层面可预期**的问题 | 进入对应业务状态（如「待修正」），由用户处理 |
| **基础设施异常** | 外部服务不可用、超时、系统故障等**技术层面**的问题 | 进入异常状态，保留重试入口，记录留痕 |
