# TV-06：多次回滚与重新执行的一致性

## 验证结论

**可行，但库存移动记录会累积；必须通过处理步骤状态和移动关联保证业务幂等。**

## 允许的操作序列

```text
清除
→ 回滚清除
→ 重新清除
→ 入库
→ 回滚入库
→ 重新入库
```

每次执行都应创建新的库存移动，不应删除历史移动。

## 预期数据行为

| 数据 | 预期 |
|---|---|
| `stock.quant` | 每个成功操作后反映当前库存 |
| `stock.move` | 原始 move 和反向 move 全部保留 |
| `stock.move.line` | 全部保留，用于审计 |
| `stock.lot` | 保留，不因回滚删除 |
| 处理单 | 记录每一步当前状态和最后一次执行/回滚信息 |

## 一致性验证方法

每一步执行前后应按以下维度计算库存快照：

```python
domain = [
    ('product_id', 'in', product_ids),
    ('location_id', 'child_of', location_ids),
]

snapshot = env['stock.quant'].read_group(
    domain,
    ['quantity:sum', 'reserved_quantity:sum'],
    ['product_id', 'location_id', 'lot_id'],
    lazy=False,
)
```

应比较：

- 产品；
- 货位；
- lot/serial；
- 数量；
- owner；
- package（若适用）。

不能只比较产品总数量，否则会遗漏 Lot/SN 串位问题。

## 不变量

```text
Step 2 回滚前，Step 2 必须为 done
Step 1 回滚前，Step 2 必须为 rolled_back 或 pending
已回滚步骤不能再次回滚
未回滚步骤不能重复执行
每次重新执行必须产生新的 move 关联
```

## 技术风险

1. 移动记录会随着反复操作增长，这是审计要求而非数据错误；
2. 如果只用布尔字段，难以表达多次执行历史，应保留 move 关联；
3. 任意库存被外部业务消耗后，反向移动可能无法完全恢复；
4. 批次和序列号主数据不能随库存回滚删除；
5. 失败重试必须基于事务回滚，不能重复使用部分成功的 move；
6. 需要阻止跨步骤乱序回滚。

## 对 SRS 的影响

SRS 的回滚和重新执行语义可以保留。建议补充：

- 历史库存移动不得删除；
- 每次执行/回滚必须关联一组 move；
- 一致性验证按产品、货位、lot/serial 维度执行；
- 外部库存变化导致无法完全反向时，必须阻断并报告；
- 多次操作产生历史记录属于预期行为，不应以“move 数量不增加”作为幂等标准。
