# TV-13：连续扫描 SN 与逗号分隔批量二维码

## 验证结论

**可行。批量二维码必须后端事务原子提交，前端校验不能单独保证原子性。**

## 单个 SN

处理步骤：

1. 接收 Enter 结束的扫描值；
2. 清理首尾空白；
3. 调用后端 Serial 唯一性业务方法；
4. 成功后创建一行，数量固定为 1；
5. RPC 完成前禁止再次提交。

## 批量 SN

```javascript
const serials = value
    .split(",")
    .map((item) => item.trim())
    .filter(Boolean);
```

后端必须一次性接收整个列表，先完整校验：

- 空列表；
- 批内重复；
- 与已有有效盲盘明细重复；
- 当前产品和工作包范围；

全部通过后再一次性创建明细。任一失败都不能创建部分记录。

## 性能和风险

- 大批量二维码需要设置合理数量上限；
- 后端一次事务创建；
- 唯一冲突必须整体回滚；
- 前端应显示失败原因，不能报告成功。

SRS AC11、AC35 已明确原子性；TDD 应定义批量上限、RPC 输入结构和错误格式。
