## 4. Evaluation Baseline Analysis

1. **文件基线：** 每轮重建从最初上传附件开始；当前 Proposal、映射组和编辑决定完整写入候选文件。上一版预览是可交付版本和 Session 指针，不是后续渲染的文件输入。
2. **数据基线：** 每次 Preview/Finalize 会重新读取当前 Odoo 数据。预览保存数据指纹，Finalize 检查模板和数据指纹；发生变化时会更新预览并要求重新确认。
3. **操作历史：** Session 保存当前完整映射规则及最多 20 份规则快照；Thread 消息保留调用参数和结果。Session 没有统一的逐操作 effect 状态账本，也没有把每个历史 Preview 作为独立的操作基线保存。
4. **表达式历史：** 映射和转换随当前 Proposal 重编译；没有独立的表达式 ID 或已求值结果序列。模型重复提交同一个映射时，系统可返回 `unchanged` 和既有附件；新的映射则从原模板重新生成整份预览。
5. **结构后定位：** repeat-row 依当前选定记录及排序生成目标行；`record_target` 可按记录身份解析。坐标编辑仍按当前工作簿位置解释。跨排序/插行持续指向同一逻辑对象依赖稳定记录目标，不能从坐标本身推导。
6. **确认绑定：** 当前门禁将确认绑定到操作范围、文件字节、上下文、版本和观察值。Thread 12063 的旧返回码与这一工作区实现不一致；后续 Session 的实际成功不能解释旧 Session 失败的全部细节。
