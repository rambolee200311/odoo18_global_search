# Office AI Agent 架构与决策边界

本文件规定 Office AI Engine 及其调用方的决策边界。修改相关实现时，必须按操作的语义分类；不能仅凭异常类型决定放行或拦截。

## 四类边界

1. **业务判断由用户决定。** 是否填写、清空或替换某个业务值，是否接受模板内容变化，均不能由 `required` 元数据、旧值或模型猜测代替用户决定。未提及的目标保持原样；明确清空必须是显式操作。
2. **风险必须说明。** 覆盖已有值、公式或检测到的表头等可由用户决定的风险，应返回结构化 `needs_confirmation`，说明原值、新值、风险和精确影响范围；确认前不得写入。不得静默替用户选择，也不得把普通可决策风险永久拒绝。
3. **确认后的执行必须精确可靠。** 确认必须绑定当前 Thread、用户、Session、Proposal/Revision、文件内容指纹及操作范围。执行前重新核验这些绑定；只执行获确认的操作。`force_override` 只是重试执行的请求标记，本身不构成授权，也不能扩大授权范围。成功状态只能在实际写入、验证及交付步骤达到各自成功条件后返回。
4. **安全约束不可绕过。** Odoo ACL、Record Rules、公司隔离、目标授权范围、路径与文件安全、资源限制、结构完整性、版本一致性和保存后验证失败门禁，不得由自然语言确认或 `force_override` 绕过。

## 校验与错误处理

- 先定位校验所在层及其语义，再改动；禁止把全部 `UserError`、`ValidationError` 或 `OfficeCoreError` 批量改成警告。
- 用户可决定的风险使用结构化警告/确认；授权失败、非法操作、损坏/不受支持文件结构、资源超限、无法保证安全写入或验证器缺失/失败，应继续拒绝执行并返回可诊断错误。
- 能通过当前契约安全表达的明确操作应执行；契约或格式能力不足时应准确报告能力缺口，不得伪称成功，也不得用确认绕过技术能力缺失。
- 未提及不等于清空；模板 `required` 或 `approved_to_skip` 元数据不得自动生成用户未请求的写入、清空或丢弃澄清操作。
- 确认失效、文件变化、版本变化或操作范围变化时，必须重新评估风险并请求新的确认。

## 变更与测试要求

修改业务风险门禁时，至少测试：未确认不写入、明确确认仅执行原范围、拒绝不写入、`force_override` 单独无效、过期/范围变化需重新确认，以及权限/路径/文件完整性硬约束仍有效。

修改 Office 核心、Adapter 或 Validator 时，还须检查未修改内容、文件回读和失败候选文件不发布。测试通过不自动等于真实 Provider、浏览器或 Odoo 端到端验收通过；报告必须区分实际执行的测试层次和证据。
