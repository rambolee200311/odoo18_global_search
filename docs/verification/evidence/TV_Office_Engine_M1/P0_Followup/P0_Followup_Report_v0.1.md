## 1. 范围与结论

## 3. P0-A：真实 `.docx` 读写

**状态：`BLOCKED`。** 本轮没有合格真实 `.docx` 样本，且当前 `venv` 没有 `python-docx`。未执行保存前后结构差异、文本框/VML 检查或 PDF 视觉比较。既有合成样本和 LibreOffice 旧格式往返数据不替代本项验收。

收到样本后按下列步骤执行：

1. 在独立输入目录登记文件名、字节数、SHA-256、扩展名/ZIP 容器识别结果、`python-docx`/`lxml`/LibreOffice 精确版本。样本只在本地处理，不外传。
2. 将原件只读保留，在独立临时工作目录创建副本；仅对副本做一处预先登记的段落或表格文本替换。
3. 使用已批准且已安装的 `python-docx` 版本读取、保存、重新打开。若届时库仍未安装，先记录依赖阻塞，不自行安装。
4. 对比前后 ZIP 部件清单、`word/document.xml`、页眉/页脚 XML、关系文件、媒体清单、段落/表格/节数量和目标文本。预期修改单独注明，其他变化作为候选差异。
5. 若样本含文本框、VML、浮动对象或复杂图片关系，比较对应节点数量、文本和关系目标；发现非预期删除/改变则记 `FAIL` 或 `PARTIAL`，不能以重新打开成功代替保真检查。
6. 环境允许时分别将前后副本用 LibreOffice 导为 PDF，记录版本、命令、返回码和页面图；视觉结果需人工检查。渲染不可用时记录 `NOT RUN` 及原因。
7. 结果 JSON 记录原件 SHA-256、测试副本路径、结构计数/摘要、修改目标、输出哈希、差异证据和状态。不得记录业务字段明文。

通过标准只适用于该样本及实际包含的结构：目标修改有效，关键文本、媒体关系、页眉页脚和声明要保留的结构均有证据；无未解释的关键对象损失。一次样本通过不能泛化为全部 `.docx` 兼容承诺。

## 4. P0-B：真实 `.xlsx` 公式与格式

**状态：`BLOCKED`。** 本轮没有合格真实 `.xlsx` 样本。当前 `openpyxl 3.0.9` 低于 TV Plan 候选 3.1.x；本轮没有升级依赖，也没有执行任何样本写回。上一轮合成工作簿中公式文本与缓存值的结果只属于合成夹具，不能替代本项。

收到样本后按下列步骤执行：

1. 登记原件文件名、字节数、SHA-256、工作表名、`openpyxl`/`lxml`/LibreOffice 版本，以及实际存在的公式、合并范围、关键数字格式、命名区域、数据验证、条件格式、外部链接和图片。
2. 原件只读保留；在隔离副本上只修改一个预先确定的非公式单元格，另存为新文件。
3. 用 `data_only=False` 重新读取并比较公式坐标和公式表达式；另用 `data_only=True` 读取缓存值。将“公式文本保留”“缓存存在”“计算结果正确”分开报告。
4. 对公式结果使用独立可核验的预期值。若测试 LibreOffice 重算，先记录输入公式/缓存，再转换并检查返回码、日志、公式表达式、缓存值及样式/关系变化；不触发外部链接更新，不因转换成功而判公式正确。
5. 对保存前后 OOXML 包检查 workbook/worksheet、公式 `<f>`、合并 `<mergeCell>`、样式引用、工作表关系、命名区域、图片/绘图关系、条件格式、数据验证及 external link 条目。语义对比，不要求 ZIP 字节相同。
6. 输出 `P0_Xlsx_Results.json` 补验格式的逐项状态与差异，并保留脱敏后的检查摘要。任何包含客户/员工/交易信息的单元格值不得写进日志。

通过标准分别判断公式表达式、缓存可用性、独立计算正确性、样式/数字格式和 OOXML 结构；不得以“文件能打开”作为单一通过标准。样本未包含的 Excel 功能标记为 `NOT COVERED`。

## 5. P0-C：目标 Odoo 部署资源预算

**状态：`BLOCKED`（本地开发环境盘点完成，目标预算缺失）。** 本轮发现本地 `odoo.conf` 仅有 `http_port=8091` 这一相关配置；未发现 `workers`、`limit_time_cpu`、`limit_time_real`、`limit_memory_soft`、`limit_memory_hard`。没有据 Odoo 默认值补填。没有目标主机的反向代理超时、容器/主机内存限额、队列设置或进程树 RSS。

当前不能决定同步方案安全，也不能断言必须使用 `queue_job`。上一轮 50,000 行合成 Excel 中位数 1.924 秒及可见 Python PID RSS，只是 macOS 合成测试数据，不是目标主机预算匹配证据；LibreOffice 子进程总 RSS 也未完整观测。

目标预算表和待提供项见 `P0_Resource_Budget.md`。取得信息后应：

1. 对配置来源逐项标记为 Odoo 主配置、systemd/container、反向代理、任务队列或资源监控，不记录秘密。
2. 在目标测试主机执行版本快照，并确认稳定版 LibreOffice、字体、可用内存、并发限制及可枚举进程树能力。
3. 对真实 `.docx` / `.xlsx` 测试完整读入、修改、保存、回读、必要的 LO 重算/渲染流程，重复测量每阶段墙钟时间、CPU、Python 与 LO 整个进程树峰值 RSS、失败和超时。
4. 将测量与明确配置预算比较，并记录安全余量。只有预算与实测齐备后，才评估同步、异步、限流和进程隔离；不预选 `queue_job`。
